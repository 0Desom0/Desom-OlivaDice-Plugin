# OlivaAIAgent 配置填写指南（v2.20.13）

## 零、最重要的三句话

1. **设置在哪**：OlivOS 托盘菜单选择“打开设置面板”，全部配置、群级开关和维护操作都在同一窗口。
2. **90% 的人只需要填 API Key**：进入“OpenAI / 千问兼容”，填写接口地址、API Key 和模型后点击“保存并应用”。
3. **仍可手工编辑**：配置保存在 `plugin/data/OlivaAIAgent/config.json`，外部保存后会自动热载（最多 2 秒延迟）。`.ai reload` 只用于立即重载。

> ⚠️ JSON 语法：**不能写注释**、**不能有多余逗号**、存 **UTF\-8 无 BOM**。改坏了也不怕：插件会把坏文件备份成 `config.json.bad` 并用默认值先跑着，你修好保存即可。
> 
> ⚙️ 仅两件事需要重启/手动：`agent.max_concurrent`（并发数，重启生效）；新增/修改 `skills/` 技能后发 `.ai skills reload` 重建索引。

* * *

## 一、最小可用配置（只改一处）

在 GUI 的“OpenAI / 千问兼容”页填写，或手工打开 `config.json` 修改 `openai` 段：

```json
{
  "backend": "openai",
  "openai": {
    "api_url": "https://api.deepseek.com/v1/chat/completions",
    "api_key": "sk-你自己的DeepSeekKey",
    "model": "deepseek-v4-flash"
  }
}
```

保存 → 群里发 `.ai 你好` 测试。完事。

* * *

## 二、选后端

`backend` 决定用哪一段配置：`"openai"` / `"anthropic"` / `"custom"`。

### 1\) DeepSeek / 任何 OpenAI 兼容接口（默认）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `api_url` | DeepSeek | **要带完整路径** `.../v1/chat/completions`，不是只到域名 |
| `api_key` | 空 | 唯一必填 |
| `model` | `deepseek-v4-flash` | 快/便宜；要更强用 `deepseek-v4-pro`。**旧名 deepseek\-chat / deepseek\-reasoner 已于 2026\-07\-24 官方弃用** |
| `stream` | `false` | 群聊机器人不需要打字机效果，保持 false 即可 |
| `temperature` / `max_tokens` | `0.7` / `2000` | 常规采样参数 |
| `vision` | `false` | 主模型是否支持看图（GPT\-4o/Claude 这类多模态填 true，配合 vision 段的 auto 路由） |
| `thinking` | `{"type":"disabled"}` | 思考模式开关：DeepSeek V4 默认开启，官方 DeepSeek 地址会显式下发 `disabled` 以免产生隐藏推理 Token；`enabled` 配合 `reasoning_effort`\: high/max。其他严格 OpenAI 端不会收到 disabled 扩展参数 |
| `timeout_sec` | `120` | 单次请求超时 |
| `extra_headers` / `extra_body` | `{}` | 某些中转要的额外请求头/报文字段，一般留空 |

- 官方 OpenAI：`api_url` 换 `https://api.openai.com/v1/chat/completions`，model 填 `gpt-5` 等。
- 硅基流动：`https://api.siliconflow.cn/v1/chat/completions` \+ 它支持的模型名。

### 2\) Anthropic（Claude 官方）

`backend:"anthropic"`，填 `anthropic` 段：`api_url`（默认官方 `/v1/messages`）、`api_key`、`model`（如 `claude-sonnet-4-20250514`）、`anthropic_version`（默认即可）。`vision` 默认 true。

### 3\) custom（自定义网关）

中转/网关既不是标准 openai 也不是 anthropic 时用：`wire` 选 `"openai"` / `"anthropic"` / `"responses"` 决定报文格式，其余字段同上。

### 4\) OpenAI Responses API（/v1/responses）

**把 `api_url` 指到 `.../responses` 结尾即可自动切换报文格式**，别的不用动；也可显式写 `"wire":"responses"` 强制。思考模型配 `thinking:{"type":"enabled"}` \+ `reasoning_effort`，自动转成 `reasoning.effort`。骰点/工具/识图/流式与普通模式完全一致。

## 三、逐段字段详解

### trigger — 怎么触发 AI

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `prefix` | `[".ai","。ai","/ai"]` | 群与私聊共用的显式前缀，不提供群级覆盖 |
| `at_trigger` | `true` | 潜行开启时，@机器人是否跳过概率并进入前置小模型；潜行关闭时不触发 |
| `keywords` | `[]` | 所有群共用的触发关键词；潜行开/关都认，命中即跳过概率和前置小模型进入主模型，主模型仍可判断是否开口。如 `["骰娘","先攻"]` |
| `private_chat` | `true` | 私聊总开关：`false` \= 私聊完全不可用（含 `.ai` 指令） |
| `private_master_only` | `true` | `true`\=私聊只有骰主能用；`false`\=所有人可私聊（仍受总开关约束） |
| `ignore_command_regex` | `^[.。/].+` | 形如指令的消息不当聊天处理（防误触发） |

> 触发逻辑速记：群开关关闭 = 全部 AI 入口关闭；群开关开启但潜行关闭 = 只认本群前缀和关键词；潜行开启后才额外响应 @、引用机器人和概率主动插话。

### 群级设置 — 群列表、白名单和触发项

`groups.json` 是唯一群列表，不再在 `config.json` 保存第二份 `whitelist.groups`：

- 白名单模式开启：只有群级设置表中存在的群有触发资格。
- 白名单模式关闭：所有群都有触发资格，再由群开关或“新群默认启用”决定是否运行。
- 群开关关闭：潜行、前缀、关键词、@、引用全部关闭。
- 潜行关闭：只保留本群前缀和关键词；@、引用和普通消息不触发，也不为普通消息调用记忆模型。
- 群前缀/关键词留空表示继承全局默认，填写 `[]` 表示本群明确禁用。

GUI 的“群级设置”页同时放置全局启用、白名单模式、新群默认启用、新群潜行默认启用，以及所有群共用的前缀和关键词。每群只覆盖插件、潜行、高危工具和记忆开关；同一群 ID 只保存一条记录。指令 `.ai wl on/off/add/del/list` 操作同一份群列表。

### permissions — 高危接口权限（踢人/禁言/撤回等）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `admin_tools_global` | `true` | 高危接口全局总开关 |
| `admin_tools_min_role` | `"everyone"` | 角色门槛：`everyone` / `group_admin`(群管理\+群主\+骰主) / `master`(仅骰主)。指令 `.ai admin role xxx` |

> `olivos_call` 是唯一的 OlivOS 原生调用入口，无论查询、发言还是群管都经过这道闸门；`olivos_discover` 只读内存目录，不执行接口。`run_command` 重注入的骰系指令仍由骰系自己按发送者身份判权，原生操作最终还受机器人账号实际权限限制。

### masters — 谁是骰主

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `from_olivadice` | `true` | 沿用 OlivaDice 骰主名单（推荐）；群链下主账号的骰主在从账号上也会被认作骰主 |
| `extra` | `[]` | 额外骰主 QQ / openid 列表 |
| `default_title` | `"骰主"` | 已验证为骰主、但没有专属映射时使用的称呼 |
| `titles` | `{}` | 按真实发送者 QQ / openid 精确设置专属称呼，如 `{"10001":"主人","10002":"主人小号"}` |

“是否为骰主”只由 OlivaDiceCore 和 `extra` 判定，“该怎么称呼”只由 `titles` 和 `default_title` 判定。人设提示词、昵称、@、引用、群聊历史、记忆及用户自己的声明都不能改变这两个结果；因此不要再把主人 QQ / openid 写进 `prompt.system`。

### groupchain — 群链 / 主账号数据共享

`enable: true`（默认）：读取骰系（OlivaDiceCore）的主从账号关系，**从账号的记忆/知识/侧写/群总结自动写入主账号**，同一主账号下多 bot 共享一份数据；`false` 则各 bot 独立。主从关系在骰系里配，`.ai status` 可查看本 bot 是否已并入主账号。

### olivadice_logger — 团日志记录兼容

`enabled: true`（默认）：检测到 OlivaDiceCore 后，把本插件成功发送的内容交给 Core 的 `msgHook`，供 OlivaDiceLogger 写入当前团日志。文本和 Markdown 直接记录；图片为 `[图片：内容]`；语音为 `[语音:内容]`。图片不记录本地文件路径，语音直接使用合成时已有的原文。没有安装 Core 时自动跳过；关闭后只停止日志补记，不影响正常发送。GUI 在“OlivaDice 团日志”中提供开关，运行维护页显示检测状态。是否实际写入文件仍取决于该群是否已经用 Logger 开团。

`record_other_plugin_messages: true`（默认）：同一个 `msgHook` 的**反向**用法——骰系插件（骰点、剧情、娱乐等经 OlivaDiceCore 发送的消息）发到群里的内容会补进潜行上下文和群滚动缓冲，AI 因此知道刚才骰出了什么。这类记录在历史里的发言者标为 `骰系插件(机器人名)`，作为群内第三方发言注入（不是 AI 自己的 assistant 轮次），提示词已要求不要冒充或复述。只覆盖走 Core 发送的插件；直接调用 OlivOS 接口的第三方插件捕获不到。仅在该群潜行开启时记录，与群上下文的既有规则一致。

### prompt — 人设与提示词

| 字段 | 说明 |
| --- | --- |
| `system` | 主系统提示词（已内置通用版），定制 AI 性格/规则改这里 |
| `group_persona` | 按群单独人设：`{"群号":"你在这个团是严肃主持人"}` |
| `dice_cheatsheet` | 骰系指令速查（已内置）。第三方插件的常用指令可以追加在这里；不写也能通过 `olivos_discover` 查 `proc.get_plugin_list`，再用 `.help` 现场查询 |

> 全局系统规则与人设只使用 `prompt.system`。升级时旧 `ambient.personality` 和 `prompt.append` 会自动合并到这里，不会丢失内容。

### memory — 记忆（会话共享记忆）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `max_rounds` | `8` | Agent 常态保留多少轮单人对话历史 |
| `prompt_cache_optimized` | `true` | 会话历史增长到缓存上限后再批量换代，避免满额后每轮滑窗使前缀失效 |
| `prompt_cache_max_rounds` | `16` | 缓存优化时会话最多增长到多少轮；换代后回落到 `max_rounds` |
| `user_memory_limit` | `40` | 个人维度长期记忆条数上限（私聊会话用） |
| `group_memory_limit` | `40` | 群会话长期记忆条数上限（群聊共享一份） |
| `context_buffer` | `20` | 群滚动上下文缓冲条数 |
| `inject_group_buffer` | `true` | 是否把最近群聊注入给 AI 作参考 |
| `history_summary_default` | `true` | 新群默认开启滚动摘要；可用 `.ai memory history on/off` 按群覆盖 |
| `long_term_default` | `true` | 新群默认开启长期事实；可用 `.ai memory long on/off` 按群覆盖 |
| `extraction_batch_size` | `8` | 累积多少条新增群记录后调用一次后台提炼 |

> **记忆 \= 会话记忆**：`memory_save` 记的是当前会话的长期记忆——群聊里**全群共享一份**（团务约定、剧情进度、房规），私聊相当于**你与机器人两人的小群**独立一份。**个人维度不单独记**：某人的性格/习惯由潜行**侧写**自动积累；跨群通用设定用 `kb_save` 进知识库。`.ai mem` 查看本会话记忆；群里 `.ai mem clear` 仅骰主可用。

### semantic_memory — 群长期事实与向量检索

长期事实存入 `semantic_memory.sqlite3`，按 bot、平台和**作用域**隔离。它与 `.ai mem` 的手动会话记忆是两套数据。

作用域有两种，由后台提炼时自动判定：

- `scope=group`：本群剧情进度、团务约定等只在本群成立的事实，只在该群召回。
- `scope=user`：提炼时带上了 `user_id` 的个人事实（长期偏好、身份、习惯、人物卡归属等），**跟着这个人在所有群和私聊召回**；只对本人生效，别人问不会命中。模型编造的 `user_id` 会被本批聊天记录校验掉。

群聊里两种作用域一起检索并按分数合并；私聊没有群号，只召回该用户自己的跨群事实。`.ai memory status` 会显示“本群 N 条 | 你的跨群 N 条”。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `embedding_api_url` | 空 | 独立 OpenAI-compatible 地址；填到 `/v1` 会自动追加 `/embeddings`，也可填完整路径 |
| `embedding_api_key` | 空 | embedding 接口密钥，不复用聊天后端密钥 |
| `embedding_model` | `qwen3.7-text-embedding` | 默认推荐通义千问纯文本向量模型；接口也可换成其他兼容模型 |
| `embedding_timeout_sec` | `30` | 单次请求超时 |
| `failure_backoff_sec` | `300` | 接口失败后暂停请求秒数，期间关键词降级 |
| `top_k` / `min_score` | `6` / `0.25` | 每轮最多注入条数 / 最低向量相关度 |

未配置 embedding 仍可启用长期事实，插件会保存事实并按关键词检索；`.ai status` 会显示“关键词降级”。

### message_registry — 消息 ID 与引用恢复

插件会把已收到/发出的消息 ID、引用 ID、QQ `msg_idx/ref_msg_idx`、出站 `ref_idx` 和正文写入自己的
`message_registry.sqlite3`。当前引用按 `[引用上文:引用正文] 当前文字` 作为本轮最后一条用户消息交给模型，
因此旧引用的话题优先于近期无关上下文；引用正文恢复失败时，机器人会说明看不到该回复并继续处理当前文字。

若同时部署本次配套的 OlivOS `qqGuildv2SDK` 修改，单个被动消息 ID 达到次数上限后会轮换同一会话
5 分钟内的其他入站消息 ID，确认没有可用候选后才退回主动发送。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `retention_days` | `7` | 消息标识和正文保留天数 |
| `max_records` | `50000` | 注册表最多记录数，超出时淘汰最旧记录 |
| `content_max_chars` | `4096` | 单条消息正文保存上限 |

### search — 联网搜索

`enabled`(true) / `tavily_api_key`（填了用 Tavily 效果好，**留空自动用 DuckDuckGo**，不填也能搜）/ `max_results`(5) / `fetch_url_max_chars`(5000) / `fetch_url_max_bytes`(2097152，单页最多下载 2 MiB) / `allow_private_network`(false，默认禁止访问机器人本机和局域网地址)。`fetch_url` 会抽取网页标题和 `article/main` 正文，而不是把整页 HTML 直接交给模型。

> 注意 `fetch_url_max_chars` 只在**主模型自己调用** `fetch_url` 时受 `agent.tool_result_max_chars`(3500) 二次限制——超出部分会被裸截。走下面的前置检索时不存在这个问题，正文由前置模型压缩后才进主模型。

### research — 前置检索（省 Token）

把「要不要联网、搜什么词、只读检索」整段搬到便宜的前置模型上：前置模型规划 → 插件直接执行检索 → 结论压缩后作为一段上下文注入主模型。主模型因此少跑一到两轮完整 prompt（原来一次联网要花掉"出 tool_call → 结果回灌 → 再组织答案 →JSON 收尾"三四次完整请求）。

**只覆盖只读检索**：`web_search`、`fetch_url`、`kb_search`、`memory_list`、`list_reminders`。骰点 `run_command`、OlivOS 接口 `olivos_call`、写库 `memory_save`/`kb_save`、发语音 `send_voice` 仍然由主模型决定——这些参数错了会真的产生错误结果或副作用。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enable` | `true` | 总开关 |
| `mode` | `auto` | `auto`=配好 `ambient.intent_api` 才前置化，没配就完全退回主模型自调工具；`always`=没有前置模型也用主模型做规划与压缩（调用次数更多，通常更贵）；`off`=关闭 |
| `max_queries` | `2` | 单轮最多几条搜索词；前置模型会把口语问题改写成精确关键词 |
| `max_urls` / `allow_fetch` | `1` / `true` | 消息里出现网址时最多抓几个页面 |
| `max_results` | `5` | 每条搜索词取几条结果 |
| `summary_max_chars` | `600` | 注入主模型的结论字数上限 |
| `prefer_provider_answer` | `true` | Tavily 已返回 `answer` 时直接采用，省掉一次压缩模型调用 |
| `readonly_tools` | `true` | 是否把 `kb_search`/`memory_list`/`list_reminders` 也交给前置执行 |
| `timeout_sec` | `30` | 前置模型单次超时 |

**回退语义**：规划失败或返回非 JSON → 整条链放弃，工具原样留给主模型；搜索一条都没查到 → 联网工具放回主模型并告知"没查到"；结论压缩失败 → 退用 Tavily `answer`，再退用原始摘要按结论预算限长。任何一步失败都不会削减能力，只是丢掉省 token 的收益。

前置成功后，被代跑的工具会从本轮工具列表里摘掉（在家族扩展之后摘，不会被 `web_search↔fetch_url` 成对加回），并在提示词里注明"已由前置模型完成，不必重复调用工具"。日志里可以按 `research.plan` / `research.executed` / `research.summary` / `research.preflight` 追踪每一步。

### mcp — 外部 MCP 工具

在 GUI 的“MCP 服务”中启用并编辑 `servers` JSON，保存后到“运行维护”点击“刷新 MCP 工具”。

```json
[
  {
    "name": "remote",
    "enabled": true,
    "transport": "streamable_http",
    "url": "https://example.com/mcp",
    "headers": {"Authorization": "Bearer xxx"},
    "danger": true
  },
  {
    "name": "local",
    "enabled": true,
    "transport": "stdio",
    "command": "npx",
    "args": ["-y", "@example/mcp-server"],
    "env": {},
    "danger": true
  }
]
```

`danger:true` 表示该服务的工具受“工具权限”三级管控，建议保持开启。HTTP 认证放在 `headers`；stdio 不经过 shell，`command` 与 `args` 分开填写。运行状态会显示已连接服务数和动态工具数。

### ambient — 潜行模式（伪装群友、择机插话）

默认关闭，按群 `.ai stealth on` 开。常改的：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `reply_probability` | `1.0` | 普通消息自行插话概率；@/引用机器人不受此概率影响 |
| `standalone_emoji_reply_probability` | `0.05` | 只有表情包（无文字）时的插话概率；表情包仍会识图并写入上下文，只是默认不专门回复 |
| `integrate_hard_trigger` | `true` | 被@/引用机器人/命中关键词时整合潜行上下文和全部工具（推荐开） |
| `allow_tools` | `false` | 被动插话是否也能调工具/骰点（开了更强但更费 token） |
| `first_thinking` | `false` | 前置判定：先用便宜小模型判断该不该接话，活跃群建议开（配 `intent_api`） |
| `history_size` | `8` | 每次带多少条群历史 |
| `intent_history_size` | `0` | 前置辅助模型读取的最近群历史条数；`0`=与当前群聊历史同步，超过现有历史时按现有历史截断 |
| `prompt_cache_history_size` | `16` | 潜行历史最多增长到多少条；换代后回落到 `history_size` |
| `slack_time` / `slack_cooldown_time` | `5` / `30` | 节律：等人说完再回 / 冷却 |
| `prompt_cache_optimized` | `true` | 前缀缓存优化，省 token，保持开 |
| `record_memory` / `record_knowledge` | `true` | 兼容旧版的侧写 / 动态知识开关；群摘要与长期事实改由 `.ai memory ...` 独立控制 |

进阶（一般不动）：`ignore_prefixes`（指令不当聊天）、`history_dynamic*`、`max_message_length`、`retry_count`、`search_ageing`、`agent_max_turns`、`max_send_delay`（拟人打字延迟上限）、`intent_image_cache_size`。

> 省钱组合：`first_thinking:true` \+ `intent_api` 填个便宜模型（如硅基流动 Qwen 7B）。每条消息会按需并行执行独立的参与、图片和工具判断，输出支持非 JSON 正则兜底；该辅助模型也承担后台记忆提炼与技能元数据翻译，但不生成任何用户可见回复。定时提醒正文由主模型在创建任务的现有工具轮中一并写好，到点不再调用模型。主模型只接收整理结果和本轮相关工具，`allow_tools` 可以保持开启。

> 判断顺序：普通潜行消息先经过概率，命中后由前置模型给出 `NEXT/SKIP`，`NEXT` 后主模型仍可二次判断，默认沉默。被@或引用机器人会跳过概率，直接进入前置模型；`NEXT` 后主模型必须回应，`SKIP` 则结束。触发词跳过小模型后仍由主模型二次判断是否开口；只有 `.ai` 跳过小模型并直接要求主模型回应。前置与主模型共享图片候选：前置可以建议图片，主模型也可自行采用、改选或不发；显式 Agent/私聊主模型同样能通过 `[发图片:...]` 使用缓存图片。当前插件会用中文日志明确打印每一步决定。

“中国”“我国”“国内”等普通地域表达不会单独触发内置政治保护；需要有明确政治话题或人物语义才会拦截。

政治类选装词表可采用 MIT 许可的 `konsheng/Sensitive-lexicon` 中 `Vocabulary/政治类型.txt`。请自行下载到本机并填写路径；不要直接启用来源不明或不分类型的全量词库，否则角色名、历史名词和跑团文本容易误伤。插件内置 Trie 匹配，无需安装 `pyahocorasick`。

也可以在 GUI 的“内容与人设安全”点击“下载 / 检查更新”，或在“运行维护”点击“在线安装 / 检查更新”；两个入口共用同一份状态与更新逻辑。插件会下载到数据目录的 `sensitive_words` 子目录，自动启用并写入配置；以后再次点击会根据 ETag/Last-Modified 检查更新。只有通过大小、UTF-8 和有效词数校验的内容才会原子替换旧文件，联网失败不会删除当前词库。

### voice — 语音模型与自主语音回复

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 启用后向 AI 提供 `send_voice` 工具 |
| `provider` | `dashscope_multimodal` | `dashscope_multimodal`=阿里云百炼原生非流式接口；`openai_compatible`=兼容 `/audio/speech`；`mimo_tts`=小米 MIMO Chat Completions TTS |
| `api_url` | DashScope `/multimodal-generation/generation` | 北京地域官方原生 HTTP 地址；新加坡地域按阿里云文档换成对应地址和 API Key。`mimo_tts` 默认 `https://api.xiaomimimo.com/v1/chat/completions`，若仍填百炼默认地址会自动改到 MIMO |
| `api_key` | 空 | 语音接口密钥，可与聊天模型不同。MIMO 同时发送 `api-key` 与 Bearer |
| `model` | `qwen3-tts-instruct-flash` | 支持自然语言语音表现指令；不需要指令控制时也可改为 `qwen3-tts-flash`。`mimo_tts` 会按 `mimo_mode` 自动选用 `mimo-v2.5-tts` / `mimo-v2.5-tts-voiceclone` / `mimo-v2.5-tts-voicedesign` |
| `voice` | `Cherry` | 固定音色；AI 只能决定是否发语音，不能擅自切换配置音色。`mimo_tts` + `default` 用预置音色：`mimo_default` / `冰糖` / `茉莉` / `苏打` / `白桦` / `Mia` / `Chloe` / `Milo` / `Dean`，百炼旧音色名会落到 `冰糖` |
| `mimo_mode` | `default` | 仅 `mimo_tts`：`default` 选预置音色；`clone` 选参考音频文件；`design`/`create` 自己写音色 prompt |
| `clone_audio` | 空 | 仅 `clone`：wav/mp3 绝对路径或相对路径，或 `data:audio/...;base64,...`。相对路径会依次在插件目录、`data/voice`、`tts_samples`、`试听_*` 下查找。GUI 可点“浏览”填绝对路径。Base64 不超过 10MB |
| `design_prompt` | 空 | 仅 `design`：自己输入音色描述，写入 MIMO 的 user 消息。留空则按 `prompt.system` 生成，不是第二套人格提示词 |
| `optimize_text_preview` | `false` | 仅 MIMO `design`：是否让接口润色朗读文本 |
| `language_type` | `Chinese` | 建议与朗读文本语种一致，也可填写 `Auto`、`English` 等官方支持值 |
| `optimize_instructions` | `true` | 让阿里云优化 AI 针对本次上下文动态生成的声音表现指令 |
| `response_format` | `mp3` | `openai_compatible` 与 `mimo_tts` 使用；MIMO 支持 `wav`/`mp3`/`pcm16`，其它值落到 `wav`。阿里云原生模式按返回音频的真实格式保存 |
| `speed` | `1.0` | 只用于 `openai_compatible`；阿里云原生模式请通过 `instructions` 控制语速 |
| `max_chars` / `max_bytes` | `500` / `15728640` | 单次文本与音频大小限制 |
| `max_files` | `100` | `voice/` 本地缓存文件数 |

阿里云模式固定发送 `parameters.stream=false`，报文等价于官方 `dashscope.MultiModalConversation.call(..., stream=False)`，但插件继续用内置 `requests` 直连，不需要安装 `dashscope` SDK。接口响应中的 `output.audio.url` 会在 24 小时有效期内立即下载到本地。官方当前示例返回 WAV，插件不会把 WAV 内容伪装成 MP3，而会识别真实扩展名后交给 OlivOS 标准 `record` 消息段；QQ 富媒体文档当前支持 `silk/mp3/wav/ogg` 语音格式。

MIMO 报文把朗读文本放在 `assistant` 消息，把本次 `instructions` 放在 `user` 消息；`design` 会把 `design_prompt` 与本次朗读指导拼进同一条 user 消息。`clone` 未配置参考音频时工具不可用。

语音行为仍由唯一的 `prompt.system` 决定，没有语音专用人格提示词。主模型调用 `send_voice` 时会在同一次工具调用里生成 `text`（说什么）和 `instructions`（这一次怎么念），因此声音表现能结合当前对话、情绪和语境；不会额外请求一次模型，也不会把动态指令写进配置或长期记忆。同一次 AI 回复内，忽略空白差异后的相同 `text` 只会合成并发送一次，内容不同的分段仍可分别发送。GUI 不再提供固定 `instructions` 输入框，升级时旧字段会自动移除。`qwen3-tts-flash` 等非 Instruct 模型与 OpenAI-compatible 接口会忽略动态指令。工具调用只记录一条明显的开始日志，拦截重复语音时只额外记录一条跳过日志；QQ Guild V2 会走适配器现有的音频上传路径。旧版没有 `provider` 的 `/audio/speech` 配置会自动迁移为 `openai_compatible`，不会改变原有请求格式。

### reply / enable / debug\_log

- `reply`：`qqguild_auto_markdown`(true) 检测到标题、粗体、列表、表格、代码块、链接等 Markdown 语法时，qqGuildv2 自动改用原生 Markdown 消息，失败退回普通回复；`quote_reply`(true) 允许 AI 根据语境自主引用本会话内的近期消息；`split_length`(1500)/`max_split_count`(3) 长回复分段。
- `file_logging`：`enable`(true) 把插件运行日志按天写入 `plugin/data/OlivaAIAgent/logs/`；`retention_days`(14) 自动清理过期日志；`max_file_mb`(20) 达到上限后在当天轮转新文件。写入前沿用流程日志脱敏，并额外隐藏密钥、令牌、媒体 Base64 与常见签名参数。
- `enable`：`global`(true) 总开关；`group_default`(true) 新群默认可用。这两项在 GUI“群级设置”页修改。
- `debug_log`(true)：详细流程日志（缓存命中率、工具调用），排查问题用；关闭后普通启动/错误日志仍按 `file_logging` 设置落盘。

## 四、官机（qqGuildv2）能力边界

插件没有手写 Event/SDK 工具。启动时把 Event、Proc、全部 SDK 及已加载 SDK 的 `indeAPI` 写入内存目录；所有原生能力都先由 `olivos_discover` 查真实签名，再由 `olivos_call` 调用。若本地 OlivOS 没实现，AI 会明确说明不可用，不会猜接口或假装成功。

本地 `qqGuildv2` 已实现原生 Markdown：模型搜索 `markdown` 时会发现 `inde.create_markdown_message`，可以传 `chat_type`、`chat_id`、`markdown`、`keyboard` 等真实参数，无需在插件里再写一个 QQ 专用分支。以后 SDK 增加其他公开方法，插件重载后也会自动进入目录。

`create_markdown_message` 是直接发送接口，调用成功就已经把 Markdown 发出去了；它不是把 Markdown 返回给普通回复继续发送。普通聊天仍走插件最终回复，用户明确需要 Markdown、键盘或主动发送时，模型可自行改用发现到的专用接口。运行期提示会要求它在专用接口成功后不要再普通回复同一份内容，避免重复发送。

qqGuildv2 中包含 `@` 用户的回复应使用 Markdown 格式发送。模型会优先选择 `inde.create_markdown_message`；如果普通最终回复仍带有 OP/CQ at 段或 `<qqbot-at-user>` 标签，插件会复用 SDK 的 at 转换并自动改走 Markdown，专用接口失败时才退回原普通发送链路。

qqGuildv2 公域连接可能收到两类“群消息”：QQ 群事件应使用 `qq_group`，频道子频道事件应使用 `guild_channel`。插件会读取当前事件的 `flag_from_qq/flag_from_direct` 自动推导 `chat_type/chat_id`；模型不需要也不允许编造 `CURRENT_CHANNEL` 一类占位符。即使模型误写 `guild` 或 `channel`，调用器也会在执行前纠正为当前真实会话。

> `olivos_discover` 仅查看目录；`olivos_call` 能调用底层原始接口，因此整体受 `.ai admin global/on/role` 的高危权限门槛控制。建议公开群使用 `.ai admin role master` 或至少 `group_admin`。

| 能力 | QQ群(官机) | 频道(官机) | onebot(NapCat等) |
| --- | --- | --- | --- |
| 发消息/骰点/AI对话 | ✅ | ✅ | ✅ |
| 撤回 | ✅ 仅机器人自己2分钟内的消息 | ✅ | ✅ 含撤他人(需管理) |
| 定时提醒 | ✅ 主动推送 | ✅ | ✅ |
| 图片识别 | ✅ base64 模式 | ✅ | ✅ |
| 禁言/全员禁言/踢人 | ❌ 官方未开放 | ✅ 直连实现 | ✅ |
| 贴表情回应 | ❌ | ✅ 直连实现 | ✅ |
| 群信息/成员查询 | ❌ | ✅（成员列表需私域权限） | ✅ |
| 点赞/戳一戳/打卡/群文件/公告/精华/名片 | ❌ 官方未开放 | ❌ | ✅ |

> 撤回怎么用：引用一条消息说"撤回"（onebot 直接可用）；官机说"**把你刚发的那条撤了**"（插件会捕获机器人自己发出的消息 id 注入上下文）。官方拒绝时（超2分钟/权限不足）AI 会带回官方错误原因。

## 五、常见配方

**① 只想聊天**：填 `openai.api_key`，其余不动。

**② 让它在某群像群友一样冒泡**：该群发 `.ai stealth on`；嫌吵把 `ambient.reply_probability` 调到 0.2 左右；省钱再开 `.ai stealth think on`。

**③ 要识图**：`vision.enable:true`（官机保持 `mode:"base64"`）；主模型是多模态就把后端段 `vision:true`，纯文本就填独立 OCR 模型。

**④ 定时提醒**：直接对 AI 说「三小时后提醒我喝水」「12:52 给我发开会」「明天上午9点叫我起床」，到点它会主动来找你。说「取消提醒」或「列出我的提醒」可管理。**仅支持一次性提醒，不支持"每天/每周"循环**——循环需求请用 OlivaDice 的 `.sn` 跑团名片或外部定时器配合。

**⑤ 大群防滥用**：`.ai admin role master`（高危接口仅骰主），或 `.ai admin off` 关掉本群高危接口。

**⑥ 只在几个群启用**：`.ai wl on` \+ 各群 `.ai wl add`。

## 六、指令速查（多数配置不用改 JSON）

| 指令 | 作用 | 权限 |
| --- | --- | --- |
| `.ai <内容>` | 对话（骰点\+全接口\+定时提醒） | 所有人 |
| `.ai status` | 看后端/开关/群链/技能引擎状态 | 所有人 |
| `.ai clear` | 清自己的对话历史 | 所有人 |
| `.ai mem` / `.ai mem clear` | 看/清本会话长期记忆 | 群里 clear 仅骰主 |
| `.ai memory status` | 看本群滚动摘要、长期事实及向量状态 | 所有人 |
| `.ai memory history on/off` | 本群滚动摘要开关 | 骰主 |
| `.ai memory long on/off` | 本群长期事实开关 | 骰主 |
| `.ai on` / `.ai off` / `.ai global on/off` | 本群/全局开关 | 骰主 |
| `.ai stealth on/off` | 本群潜行模式；关闭后只认本群前缀和关键词 | 骰主 |
| `.ai stealth think on/off` / `.ai stealth tools on/off` | 前置判定 / 潜行带工具 | 骰主 |
| `.ai admin role everyone/group_admin/master` | 高危接口门槛 | 骰主 |
| `.ai admin on/off` / `.ai admin global on/off` | 本群/全局高危开关 | 骰主 |
| `.ai wl on/off/add/del/list` | 白名单模式与统一群列表 | 骰主 |
| `.ai model <模型名>` | 临时切模型 | 骰主 |
| `.ai skills reload` / `.ai kb reload` / `.ai reload` | 重建技能索引 / 重载知识库 / 重载配置 | 骰主 |

定时提醒、撤回、禁言这些都不用记指令——直接对 AI 说自然语言（「三小时后提醒我」「12:52 给我发开会」「把你刚发的撤了」），它自己调工具。

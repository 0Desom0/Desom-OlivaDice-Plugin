# QQ 官方机器人控制台

## 部署

将 `QQOfficialConsole/` 放入 OlivOS 的 `plugin/app/`；也可把目录**内部**的文件打包为 ZIP 并改扩展名为 `.opk`，包根目录必须直接包含 `app.json`、`__init__.py`、Python 模块及 `webui/index.html`。需要支持插件 WebUI 和当前 `qqGuildv2_link` SDK 的 OlivOS；仅从宿主侧栏「插件页面」打开，直接打开页面不具备消息桥。`app.json` 为 UTF-8 无 BOM，部署前检查开头不是 `EF BB BF`。

WebUI 登录者可向机器人能访问的会话发言及执行其有权限的操作；请保护宿主访问地址，不要将未受保护的控制台暴露到公网。插件不向网页提供机器人凭据，也不额外监听网络端口。

## 使用与数据

- 群和私聊显示在同一会话列表，分别标记「群」和「好友」；完整的 group_openid / user_openid 显示在副标题。没有官方群/好友列表时，可手动添加 openid，事件也会自动建立会话。
- 首次打开只加载最近 30 条，向上滚动加载更早消息；切走后的已加载内容和滚动位置缓存 30 分钟，切回后只增量获取新消息。缓存为临时磁盘数据，和永久消息库分开；不设总容量上限，磁盘空间不足时会提示且保留当前会话。缓存较多时请留意可用磁盘空间。
- 平台明确投递的群 @ 机器人消息会显示会话和账号角标，页面可见时提示；是否开启全量消息都适用。仅收到无法判断是否 @ 的全量消息时不猜测。进入会话不会自动跳转，点击标题栏「@我」定位最早未读提及；目标后不超过 300 条时加载连续上下文，否则只加载目标附近并可向下分页。看到对应消息后提醒清除。
- 消息按账号、会话分别保存在 `plugin/data/QQOfficialConsole/<bot_hash>/msg/qq_group/<safe_id>.sqlite3`（群）或 `.../msg/qq_private/<safe_id>.sqlite3`（私聊）。`messages` 是该会话的消息，`members` 是该会话见过的人员，`passive_tokens` 是该会话的回复凭据，`join_requests` 是该群入群申请缓存；会话列表和群/私聊类型在该账号 `meta.sqlite3` 的 `chats` 表，跨账号设置位于 `global.sqlite3`。消息默认不删除；隐藏会话或撤回不会删除历史。请按常规备份整个数据目录及 SQLite WAL 文件。
- 普通消息图片只能通过文件选择器上传，不接受图片网址。发送材料暂存于 `plugin/data/image/temp/QQOfficialConsole/`，发送流程结束后删除；已上传但未发送的残留会按时间清理。图片进入发送流程时另存副本至 `plugin/data/QQOfficialConsole/sent-images/`，即使平台发送失败也可从该消息查看；在校验阶段失败而未进入发送流程的图片不会保存。默认保留 30 天，可设置为 1–3650 天；启动时、每小时及修改设置时清理过期副本，读取时也会拒绝并清理过期副本，缩短期限立即生效。清理不删除消息记录、原始文件或永久表情。永久表情位于 `plugin/data/image/QQOfficialConsole/emoji/`，分机器人专属与全局，可上传、重命名、删除并插入消息；发送仅消费临时副本。
- 接收图片由浏览器直接访问消息中的图片地址，不由宿主代理；图片服务可看到浏览器的 IP。外部地址失效、浏览器网络或内容安全策略限制时可能无法显示。
- 群优先使用未过期被动凭据；单聊文本/Markdown 优先流式。主动发送、管理员操作、Markdown、撤回和入群申请仍受 QQ 官方账号权限与频率限制。流式请求发生网络超时后结果可能未知，不会自动重发以免重复。
- Markdown 引用会转换为正文顶部的作者和摘要引用块；消息与引用块合计计入 3000 字。其余可用原生引用的消息需有平台引用索引。超过 3000 个 Unicode 码点会在页面和服务端拦截。

## 图片桥接口

- `QQOfficialConsole_Bootstrap` 返回的全局 `settings.image_retention_days` 默认 30；使用 `QQOfficialConsole_SaveSettings` 的 `settings` 对象设置整数天数（1–3650）。
- `QQOfficialConsole_Send` 返回 `local_id` 和 `images` 数组；`PullMessages` 中对应消息的 `content_json` 是 JSON 字符串，其 `images` 与发送响应相同，每项为 `image_id`、`marker`（Markdown 图片标记，普通图片为 null）、`mime`、`size`。仅实际进入发送流程并成功保存的图片有条目；发送失败不代表图片不可查看。
- `QQOfficialConsole_MessageImageRead` 请求 `bot_hash`、`chat_type`、`chat_id`、本地消息整数 `message_id`、`image_id` 和从 0 开始的整数 `index`（省略时为 0）。成功返回 `ok`、`keyword`、`image_id`、`index`、`total_chunks`、`size`、`mime`、`data_b64`，单片最多 256 KiB；各片解码后按顺序拼接。只允许读取指定账号和会话中对应发送消息的图片；过期、不存在或无权访问返回失败，不提供服务器文件路径。收到的外部图片不通过该接口读取。

## 已知平台及宿主限制

原生图文卡片要求填写 HTTPS 跳转链接及 HTTPS 图片地址；图片地址须由 QQ 平台能够访问。群聊优先使用被动凭据，单聊通过普通消息接口发送。实际可用性与内容审核由 QQ 平台决定。参考 [群聊发送接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)。
卡片图片由浏览器直接访问 HTTPS 图片地址，图片站可看到访问者 IP；宿主的插件页面 CSP 因此允许 HTTPS 图片，其他插件页面也受此策略影响。旧版宿主未放行时只能打开图片链接。群聊标题中的人数来自事件或刷新得到的成员缓存，并非官方全量人数。

本次同步修改的 OlivOS 宿主在移动端使用独立插件视口和「返回导航」，随 `visualViewport` 调整高度；已用浏览器模拟视口缩小验证。真实手机键盘和浏览器行为尚需真机验证，旧版宿主仍可能遮挡输入区。

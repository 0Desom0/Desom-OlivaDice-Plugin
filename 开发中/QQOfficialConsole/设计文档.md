状态：方案（未写代码）
模板：官方原生 `OlivOSPluginTemplate`（只要 OlivOS + WebUI，不依赖 OlivaDiceCore）

## 1. 产品目标

在 OlivOS WebUI 里做一个收发控制台，对接 QQ 官方机器人。布局参考 QQ NT，**只做有接口（官方或 SDK）的能力；没有接口的控件不画、不做禁用态。**

必须同时覆盖：

- 群聊 `qq_group`（`group_openid`）
- 单聊 `qq_private`（`user_openid`）

能发：纯文本、Markdown、图文卡片、引用、@别人、@全体（仅群）、本地/远程选图。失败回固定关键词。收到的消息入库且默认不删。发出正文 **超过 3000 字符直接拦截**，界面实时显示当前字数。图片先落到 `plugin/data/image/temp`，随消息发出去，**发送流程结束后删除**。

发送策略（硬规则）：

| 会话 | 优先通道 | 回落 |
|---|---|---|
| 单聊 | 流式 `POST /v2/users/{openid}/stream_messages` | 卡片/富媒体/键盘等流式不支持的类型 → 普通单聊 POST；流式失败按错误码决定是否再走普通 POST |
| 群聊 | 被动回复（从本群被动池里选「未达次数上限、最快过期」的 `msg_id`/`event_id`） | 池空或平台判定被动不可用 → 主动消息 |

群聊官方明确 **不支持流式参数**，禁止把单聊流式套到群上。

## 2. 能力边界（先看这个）

官方机器人 **不是** NT 客户端。只仿有接口的交互；没接口的不画。

### 2.1 能做（走已验证接口）

| 功能 | 群 | 单聊 | 落地 |
|---|---|---|---|
| 发文本 `msg_type=0` | 是 | 是 | `indeAPI.send_qq_message` |
| 发 Markdown `msg_type=2` | 是 | 是 | `indeAPI.create_markdown_message` |
| 发图文卡片 `msg_type=8` | 是 | 是 | `indeAPI.create_card_message` |
| 引用 `message_reference` | 是 | 是 | 各发送接口 `quote_msg_id` |
| 被动 `msg_id` / `event_id` | 5 分钟 / 5 次 | 60 分钟 / 4 次 | 插件被动池选凭据，再交给 SDK 分配 `msg_seq` |
| @成员 `<qqbot-at-user>` | 是 | 是 | 含 @ 则整条改走 Markdown |
| @全体 `<qqbot-at-everyone />` | 是（管理员，每群每天 1 次） | 否，SDK 私聊直接丢掉 | 仅群、二次确认 |
| 撤回自己发的消息 | 2 分钟 | 2 分钟 | `indeAPI.delete_message` |
| 管理员撤回成员消息 | 2 分钟，用事件 `d.id` | 不适用 | 同上；非管理员会 `40062003` |
| 会话列表 | 事件自学 + 手动加 openid | 同左 | **没有群/好友列表 API** |
| 显示 group_id / user_id | 即 openid | 即 openid | 会话标题必显示 |
| 群名 / 备注 | 备注必做；官方群名接口白名单 | 备注 / 事件昵称 | 见 §6 |
| 历史、时间、搜索 | 本地库 | 本地库 | 不依赖平台漫游 |
| 错误关键词 | 是 | 是 | `data.error_code` 映射表 |
| 字数上限 3000 | 是 | 是 | 前端计数 + 后端拦截，超限关键词 `字符过多` |
| 选图发送 | 是 | 是 | 浏览器选文件 → WebUI 端口分片进进程 → `plugin/data/image/temp` → SDK 发出 → 删 temp |


### 2.2 已知缺口


1. **OlivOS SDK 没有流式发送类。** 单聊流式是官方接口，不在 `qqGuildv2SDKPrivate.API` 里。实现时在插件 `send.py` 用 SDK 现有 `api_templet` + 同一套 bot token/host，加 `POST /v2/users/{openid}/stream_messages`。禁止把 token 送到 WebUI。
2. **`GET /v2/groups/{group_openid}/info` 能返回 `group_name`，但 11253 白名单，SDK 也未封装。** 默认不当可靠群名来源。标题 = `备注 || 事件里见过的名字 || openid 截断`。
3. **`GET .../bot_state`（是否允许主动发言）同样 11253。** 主动失败用 `40034105` 关键词提示，不预检。
4. **WebUI `menu` 没有 bot 上下文。** 必须 `fake_sdk_event` 造事件。`Event.send()` 恒 `force_active=True`，**不能**用来做被动/流式。
5. **SDK 被动 `msg_seq` 在进程内存。** 重启后可能从 1 再数，触发 `40054005` 去重。插件库要持久化每条 `msg_id` 的已用次数；重启后优先换一条未用过的凭据，否则主动。

## 3. 发送策略（核心）

WebUI 点「发送」后，先定会话类型，再选通道，再选内容类型。

```text
选中会话
 ├─ qq_private ─► 流式优先（§3.1）
 └─ qq_group   ─► 被动池优先（§3.2）─► 池空则主动
```

### 3.1 单聊：流式优先

官方：群不支持流式；单聊 `content_type` = `text` | `markdown`。

**走流式（满足全部）：**

- 会话是 `qq_private`
- 内容是纯文本或 Markdown（含 @ 转 MD 后的正文）
- 不带图文卡片、不带 `media`、不带 keyboard（流式文档无这些字段）

**流程：**

1. 若被动池有可用 `msg_id`/`event_id`（单聊 60 分钟 / 4 次），流式请求带上，`msg_id` 与 `event_id` 互斥。
2. 无可用被动凭据 → 不带 `msg_id`/`event_id`，等于主动流式。可选 `is_wakeup` 默认关。
3. 人类控制台通常一次发完：
   - 短消息：一片 `index=0`，`input_state=10`（生成结束）
   - 长 Markdown（建议 > 500 字）：`index=0, input_state=1` 起，按块 `replace` 或 `append`，最后一片 `input_state=10`
   - `replace` 时后续 `content_raw` 必须以上游已下发前缀开头，否则 `40007`
4. 首片响应 `id` 即 `stream_msg_id`，后续分片原样带回。
5. 流式失败：
   - `40007` 前缀冲突 → 关键词 `流式前缀冲突`，不自动改普通 POST（会重复气泡）
   - `50002` 流式频控 → 关键词 `流式频控`，可提示稍后
   - 其他且尚未产生可见气泡 → 回落普通 `sendQQDirectMessage` / `create_markdown_message`
6. 卡片 / 富媒体 / 键盘：直接普通单聊 POST，不碰流式。
7. `msg_type=6` 输入中状态是另一接口，不当发送通道。控制台不需要「正在输入」。

WebUI 自己的气泡：本地先插一条「发送中」，流式分片只更新这一条；结束或失败再改状态。不要每个分片插一条历史。

### 3.2 群聊：被动池优先，没有再主动

群被动：同一 `msg_id` **5 分钟、最多 5 次**；`event_id` 同样 5 分钟 / 5 次。`msg_id` 与 `event_id` 互斥。

插件为每个 `(bot_hash, chat_type, chat_id)` 维护被动池（SQLite，内存镜像）。入池来源：

| 事件 | 写入字段 | TTL | 上限 |
|---|---|---|---|
| `group_message`（`flag_from_qq`） | `msg_id = message_id` | 300s | 5 |
| `private_message` | `msg_id = message_id` | 3600s | 4 |
| `button_click` / 可回复互动 | `event_id` | 群 300s / 私聊 3600s | 群 5 / 私聊 4 |
| `GROUP_ADD_ROBOT` 等官方允许用 `event_id` 回的 | `event_id` | 同上 | 同上 |

每条凭据字段：`id_type, id_value, expire_at, used_count, max_count, source_event`。

**挑选算法（群发送时）：**

```text
candidates = 本会话池中
  expire_at > now
  AND used_count < max_count
按 expire_at 升序（最快过期优先）
同过期再按 used_count 升序（剩次数多的留下，先用快没的）
取第一条
```

- 选中后调用 `indeAPI`，传入 `reply_msg_id` 或 `event_id`，**不要** `force_active=True`（SDK 规定与 `msg_id` 互斥）。
- SDK 内部 `get_msgid` / `use_eventid` 再占一次序号。插件在 **平台返回成功或 `pending_review`** 后 `used_count += 1`。
- 若 SDK 本地返回 `passive reply count exceeded` / `sequence cache is full`：这条标满，立刻换下一条候选，不先主动。
- 候选耗尽，或平台 `304103` / `40034005` / `40034128`：这条作废，换下一条；仍没有 → `force_active=True` 走主动。
- 主动触发 `40034100` 频控 / `40034105` 无权限：停止重试，回对应关键词。不要把主动失败再伪装成被动。

单聊若走流式，同样先用这套池选 `msg_id`；池空就主动流式。

UI 在输入框上方显示只读状态，例如：`被动 2/5 · 剩 1分12秒` 或 `将走主动（本群无可用被动）`。

### 3.3 内容类型路由

在通道（流式 / 被动 / 主动）定完之后：

| 用户操作 | 群 | 单聊 |
|---|---|---|
| 纯文本，无 @ | 普通 POST `msg_type=0` | 流式 `content_type=text` |
| 文本 + @人 / @全体 | **整条转 Markdown**（`create_markdown_message` 或流式 `content_type=markdown`） | 同左，全体按钮禁用 |
| 用户显式选 Markdown | MD 通道；正文里可在光标处插本地图，**禁止手填路径** | 有图则不流式，改 `create_markdown_message` |
| 图文卡片 | `create_card_message` | 普通卡片 POST（不流式） |
| 文本+图片 / 纯图 | 先落 temp 再发；有正文走 MD `local_images` 或图文；纯图 `msg_type=7` | 同左；**有图不走流式** |
| 勾选引用 | `quote_msg_id` | 同左。**带引用的图文混排 MD，SDK 会拒绝走 MD**，改为普通图文 |
| 键盘 JSON（高级） | MD/卡片可带 | 不流式 |

@ 转换规则：

- @某人：`OlivOS.qqGuildv2SDK.markdown_tag.at_user(openid)` → `<qqbot-at-user id="..." />`
- @全体：`markdown_tag.at_para(PARA.at(id='all'), allow_at_all=True, flag_qq=True)` → `<qqbot-at-everyone />`
- 私聊 `allow_at_all=False`，全体入口隐藏
- 群 @全体：发送前确认「管理员且每群每天 1 次」；失败按平台码映射

引用 ID：

- 引用别人：用入库的平台 `message_id`（事件 `d.id`）。群/C2C 场景里用户侧引用索引是 `MessageScene.ext.msg_idx`，OlivOS 收消息时已尽量换成 `PARA.reply`。
- 引用机器人自己发的：用发送响应 `ext_info.ref_idx`（`REFIDX_...`），不要只用 `ROBOT1.0_...`。入库时两套都存，引用自己优先 `ref_idx`。

### 3.4 字数上限 3000

硬限制，通道选择 **之前** 做完，避免白白消耗被动 `msg_seq` / 流式首片。

| 模式 | 计数对象 | 上限 |
|---|---|---|
| 文本 | 输入框 Unicode 码点数（`len(text)`） | 3000 |
| Markdown / 带 @ | **展开 @ 标签之后** 的 `markdown.content` / `content_raw` | 3000 |
| 卡片 | 仍用官方字段限制（title 1–50、description 1–200）；四字段拼起来不会到 3000，不走这条 |

- `@` 标签本身计入：`<qqbot-at-user id="..." />` 按展开后的字符数，不是按「@昵称」显示宽度。
- 引用、keyboard、图片路径不计入这 3000；只计将发给平台的正文。
- 单聊流式分片也受 **整条最终正文** 3000 限制，禁止靠分片绕过。
- `> 3000`：不发。前端发送按钮禁用，状态文案 **`字符过多无法发送`**，并继续显示当前字数。后端若仍收到超限 payload，回 `ok: false, keyword: "字符过多"`，不调 QQ。
- `== 3000` 允许发送。
- 空正文（0 字且无卡片）单独拦，不走这条。

### 3.5 图片：temp 落盘，发完删除

**取舍：用主人这套 temp 文件，不用 SQLite 存图。**

| | `plugin/data/image/temp`（采用） | SQLite BLOB |
|---|---|---|
| SDK | `PARA.image(file=路径)`、`local_images` 都要路径 | 还得再吐成文件或整段 base64，多一次拷贝、多占内存 |
| 单张 10MiB | 文件系统本职 | 永不删除的消息库会按图线性膨胀，备份/vacuum 都痛 |
| 外界上传 | 分片写文件 | 分片照样要组装，BLOB 没有更短路径 |
| 崩溃残留 | 按小时扫目录 | 半截 BLOB 更难清 |
| 历史回看原图 | 发完 temp 删掉，气泡只留「[图片]」+ 平台 id | 能回看，但成本是库当图床 |

收到的消息仍然入库不删，但 **只存 URL / 消息结构，不下载、不把二进制塞进库**。发出去的图是投递材料，不是档案。

浏览器拿不到本机绝对路径。**本机和外界同一条管道**：选文件 → 经 OlivOS WebUI **已有端口** 把字节送进 Python → 写 temp → 发送 → 删文件。外界不是另起一套协议，只是浏览器不在 OlivOS 那台机器上，照样走这个端口。

```text
<input type=file> / 拖拽
        │  FileReader 分片（每片 ≤ 256KiB）
        ▼
WebUI 端口 /api/plugin_event（消息桥，单请求 ≤ 1MiB）
        │  外界访问的就是这个端口
        ▼
plugin/data/image/temp/QQOfficialConsole/<upload_id>.<ext>
        │  Send 只带 upload_id，不带二进制
        ▼
SDK：纯图 send_qq_msg(PARA.image(file=绝对路径))
     或 Markdown 插图 create_markdown_message(..., local_images={marker: 路径})
        │  try/finally
        ▼
删除该 upload_id 对应 temp 文件（成功 / 失败 / 审核中都删）
```

目录固定为宿主下的 `plugin/data/image/temp/`（按主人指定）。插件只在其下写子目录 `QQOfficialConsole/`，禁止 `..`，避免和别的插件抢同一文件名。

| 规则 | 说明 |
|---|---|
| 格式 | png / jpg / jpeg / gif / webp；校验文件头，不信扩展名 |
| 单张上限 | 建议 10MiB（分片组装）；超限关键词 `图片过大`，不写完就丢弃 |
| 一次消息 | 纯文本模式 1 张；**Markdown 模式最多 9 张**，插在光标处 |
| 本机 | 仍用文件选择器 / 相册，不要让用户手填 `C:\...` 或 `{{封面}}` |
| 外界 | 同一 WebUI 端口；iframe 沙箱 `connect-src 'none'`，**禁止**页面自己 `fetch` 第二个上传口 |
| 不另开端口 | 消息桥已经在 WebUI 端口上。沙箱 `connect-src 'none'`，不另起上传 HTTP |
| 鉴权 | 分片请求走宿主已登录会话，不把 bot token 给页面 |
| 崩溃残留 | `init_after` 清 `plugin/data/image/temp/QQOfficialConsole/` 里超过 1 小时的文件 |
| 发送中崩溃 | 下次启动当残留清掉；不进 SQLite 当永久图床 |

#### Markdown 插图（和选图同一套管，不许填路径）

Markdown 编辑器不是「先写 `![x](C:\a.png)`」。光标在正文中间时点图片（或手机相册）：

1. 走上面的 `UploadBegin` / `UploadChunk`，得到 `upload_id`。
2. 在光标处插入一个 **缩略图块**（可删、可再点后面继续打字）。用户看不见路径、看不见 `{{img_0}}`。
3. 发送时前端序列化为：`markdown` 字符串里自动生成的占位符 + `images: [{upload_id, marker}]`。
4. Python 把 marker → temp 绝对路径，交给 `create_markdown_message(..., local_images={marker: path})`。SDK 负责把 `{{marker}}` 换成平台图。
5. 占位符由插件生成（`img_0`…），**输入框不提供路径字段**。

发送与删文件：

1. Python 把每个 `upload_id` 解析成 temp 绝对路径，必须仍在 `.../image/temp/QQOfficialConsole/` 内。
2. `try` 里调 SDK；`finally` 里删本次用到的全部 temp，忽略已不存在。
3. 平台侧 Markdown 素材是否保留跟 SDK 现有逻辑，**本地 temp 仍然删**。重发请重新选图。
4. 有图时单聊 **不走流式**，改普通 POST / MD。
5. **带引用的图文** 按 SDK：不走混排 MD，走普通图文路径。

卡片的 `pic_url` 必须是 https 网址，不是本地上传。本地图走图片按钮或 MD 插图。

## 4. 页面：仿 QQ NT

对照截图三栏。WebUI 沙箱：无 `localStorage`、无 `fetch`、无同源。样式自备，可用 `prefers-color-scheme`。资源全放 `webui/`。

### 4.1 左栏 · 会话

- 顶：账号切换（所有 `qqGuildv2_link` 账号，随时可切）+ **全局搜索入口**（单独一层，见 §4.4）
- 列表项：色块头像、主标题、最后预览、时间、未读角标；群若已知管理员则小「管理」角标
- 主标题：`备注 || 显示名 || openid 前 8 位`
- 副标题固定一行：`群  {group_id}` 或 `好友  {user_id}`（完整 openid，可复制）
- 右键：置顶、改备注、从列表隐藏（**不删库**）、复制 id
- `+`：手动加入 `group_openid` / `user_openid`（冷启动没有事件时）
- 群/私聊用小标签区分，不要做成两个互斥页（一个列表，类型过滤可选）

### 4.2 中栏 · 聊天

- 顶栏：主标题 + 人数（缓存）+ 管理员标记（是才显示）。**不要**在顶栏放本群搜索放大镜
- 消息：左收右发；时间（今天 `HH:mm`，跨天带日期）；发送中 / 失败关键词 / 已撤回
- 引用块：灰色条 + 原作者 + 摘要，点一下滚到原消息（库里还在才滚）
- Markdown：安全渲染（白名单标签，禁止 `innerHTML` 整包）
- 卡片：标题、描述、图、链接（https）
- 右键（能接的才亮）：复制、引用、撤回、按时间定位、查看 message_id
- 底栏：
  - 模式切换：文本 / Markdown / 卡片
  - @ 按钮：从本会话成员缓存点选；群另有 @全体（确认框）
  - **图片按钮**：文本模式 = 附件条 1 张；Markdown 模式 = **插到光标中间**，可多张缩略图块
  - 引用条：引用中时顶在输入框上，可取消
  - 字数：输入框右下角常驻 `当前 {n} / 3000`；`n > 3000` 时数字变红，旁边出现 **`字符过多无法发送`**，发送按钮禁用，Enter 也不发
  - 发送按钮始终可点。桌面快捷键可改（发送钮右侧小三角，仿 QQ）：`enter_send` = 回车发送、Ctrl+Enter 换行（默认）；`ctrl_enter_send` = 回车换行、Ctrl+Enter 发送。写入 `settings.send_key`。Mac 把 Ctrl 和 Cmd 都认。**手机不管这套：回车只换行，只能点按钮发送**
- **消息记录按钮**：输入区右侧、成员栏左侧，时钟图标（截图红框位置）。点了把右栏切成「本群消息记录」（§4.4），再点一次或点「群资料」切回去
- 被动/流式状态条见 §3.2

底栏只放实际接得上的：模式、@、图片、发送（含快捷键三角）、时钟。不画表情、红包、语音、截图、转发、收藏、多选。

### 4.3 右栏 · 资料（可折叠）

群：

- 显示名、备注（可编辑）、`group_id`（只读复制）
- 机器人身份：`普通成员` / `管理员` / `群主` / `未知`（见 §6.1）
- 成员缓存列表（事件积累；管理员且接口未 11253 时可点「刷新官方成员」）
- 本群被动池：剩余次数、过期倒计时
- **仅管理员可见的操作区**（非管理整块不渲染）：
  - @全体（每天每群 1 次确认）
  - 撤回他人消息（2 分钟，用入库的 `platform_message_id`）
  - 主动发言开关状态（`allow_proactive_msg`，只读）
  - 禁言查询/设置（SDK `restrict_chat_setting`）
  - **入群申请**：右栏入口打开独立面板（§4.7），可看全部、同意/拒绝
  - 官方成员列表刷新（内邀，11253 则提示 `无接口权限`）

单聊：

- 显示名、备注、`user_id`
- 被动池倒计时
- 无管理员区

### 4.4 查找

仿 QQ：关键词匹配，不是正则。空格分开的多个词 **同时包含**（AND）。大小写英文不敏感；中文按原文包含。搜 `content_text` 和 `sender_name`。`%` `_` 当普通字符，SQL 里转义。

**本群消息记录（右边，仿 QQ 时钟）：**

- 入口：中栏右下时钟，**不是**聊天顶栏放大镜
- 打开后右栏整页换成记录：上边搜索框 + 时间筛选，下边按日分组的消息列表（左收右发缩略）
- 只读当前 `msg/...sqlite3`；展示窗口关着也能在这里翻全量
- 可筛：关键词、时间范围、只看自己发的、含失败、含已撤回
- 点一条：中栏滚到对应气泡；没有加载的就按 cursor 补齐再定位
- 再点时钟或右栏「返回资料」：右栏回到成员/群资料

**全局搜索**（左栏顶搜索，**单独一层**，不要和右边记录混按钮）：

- 先搜 `meta.chats` 的备注 / display_name / chat_id（会话结果）
- 再按 `last_message_at` 倒序扫各会话库的 `messages`（消息结果），每群最多 20 条，全程上限 100 条
- 结果分组：会话 / 消息；消息行带群名+时间，点进去切会话并定位
- 不扫隐藏会话（`hidden=1`）除非勾选「含已隐藏」
- 一次只打开有限个 sqlite，搜完关掉，避免全局搜索把 LRU 打爆

两处都不打 QQ 平台漫游。

### 4.7 入群申请（仿 QQ，仅管理员）

官方：`GET /v2/groups/{group_openid}/join_request_list`，**机器人必须是群管理员**，30 QPM，单页默认 20、最大 50。审批：`POST .../approval_join_request/{member_openid}`，`op=approve|decline`。

UI 单独一层（像 QQ 的入群申请页），不要挤在右栏三条摘要里：

- 列表：头像色块、昵称、`apply_at`、来源（主动申请 / 被邀请 + 邀请人）、验证消息或问答、风险提示 `risk_tips`
- 每条：同意 / 拒绝（拒绝可填理由、可选拉黑）
- 顶栏：**刷新全部**（查完所有页）、未处理数量
- 空态：「暂无入群申请」
- 非管理员不进这个入口

**查询全部：** 不要只拉第一页。`limit=50`，带上一次的 `next_cursor` 循环，直到 `next_cursor` 为空。页与页之间间隔 ≥ 2 秒，守 30 QPM。保护上限 40 页（2000 条），到上限提示 `申请过多未拉完`，已拉到的仍展示。

拉下来的申请写入该群会话库 `join_requests`（见 §5.2），之后自己翻看走本地，不每滑一次打平台。同意/拒绝成功后把该行 `status` 改掉并从待处理列表拿掉，不删行。

走 SDK：`get_qq_group_join_request_list`（自己翻页，不用只拉一页的 standard 包装）和 `approve_qq_group_join_request`。

### 4.5 实时性（按账号写入，WebUI 只读）

和 OlivOS 一样：**账号收到事件就立刻入库**，不经过网页。`group_message` / `private_message` / 入群退群等，只要 `sdk == qqGuildv2_link`，按 `plugin_event.bot_info.hash` 写入 **该账号自己的目录**。WebUI 开没开、当前看的是不是这个号，都不影响写入。

沙箱不能 WS，页面看不到推送。可见时轮询 `Pull`（建议 1s）只从 **当前选中账号** 的库读 cursor 之后的行；隐藏即停。切账号立刻换库读，不中断其它号继续写。

其它号若有新未读，账号切换器上打角标（每次 Pull 顺带读各账号 `chats.unread` 合计，不打开会话库）。

### 4.6 手机端

WebUI 必须能在手机浏览器里用（外界就是连 OlivOS 端口）。三栏 NT 桌面布局在窄屏拆开，不横着挤。

| `≤ 600px` | 同上，底栏图标加大，发送按钮固定右下，时钟仍在输入区右侧 |

- 不依赖 hover

## 5. 存储

路径：`plugin/data/QQOfficialConsole/`（宿主释放目录，不进 OPK 解包路径）。

**先按账号分目录，再按会话分库。** 写入只认事件上的 bot，不认 UI 当前选中项。

```text
plugin/data/QQOfficialConsole/
├── global.sqlite3              # last_bot_hash、send_key 等跨账号设置
└── <bot_hash>/
    ├── meta.sqlite3            # 这个号的 chats
    └── msg/<chat_type>/<safe_id>.sqlite3
plugin/data/image/temp/QQOfficialConsole/   # 发出去的图，发完删
```

| 文件 | 内容 |
|---|---|
| `global.sqlite3` | 跨账号 `settings`（`send_key`、`last_bot_hash`、`poll_interval_ms`） |
| `<bot_hash>/meta.sqlite3` | 该号 `chats`；该号自己的 `view_limit_*` |
| `<bot_hash>/msg/<chat_type>/<safe_id>.sqlite3` | 该号该会话的 `messages`、`members`、`passive_tokens`、`join_requests` |

`safe_id`：`chat_id` 仅保留 `[A-Za-z0-9_-]`；否则用 `sha256(chat_id)` 的 hex，并在 `chats.safe_id` 记下。

每个 sqlite：`PRAGMA journal_mode=WAL;`。进程内 LRU 缓存打开的会话库（建议最多 8 个），切走超过 60s 关掉。`save` 对已打开的库做 `wal_checkpoint(PASSIVE)`。

收到的消息 **默认永不删除**。撤回只改 `recalled=1`。**图片二进制不进库**。列表预览只写该号 `chats.last_preview`。

切账号：WebUI 只换 `bot_hash` 再 `ListChats`。后台所有号照常收事件写自己的库。

### 5.1 展示窗口（可选，默认关）

设置项在 `global.sqlite3` 或该号 `meta.settings`：

- 跨账号：`send_key`、`last_bot_hash`、`poll_interval_ms`
- 每号：`view_limit_enabled` 默认 `false`；`view_limit_mode`；`view_limit_count`；`view_limit_days`

只影响 **打开该会话时默认加载多少**。搜索走 **当前会话那个文件** 的全量，不扫其它群。关窗口 = 该文件内按 `id` 倒序分页。

**不自动物理删除消息库，也不提供删库入口。**

## 6. 群名 / 群号 / 备注

每个群会话 **必须** 能看见 `group_id`（`group_openid`）。

显示名优先级：`备注 > display_name > openid 截断`。

`display_name` 来源：

1. 用户备注（唯一可靠、可改）
2. 若以后 SDK 封装且机器人在白名单：`GET /v2/groups/{id}/info` 的 `group_name`（11253 则忽略）
3. 不要用成员昵称冒充群名

单聊：`备注 > sender.name > user_openid 截断`。

### 6.1 机器人是不是本群管理员

打开群会话、以及 `role_updated_at` 超过 10 分钟时探测一次，结果写入 `chats.self_role`。

顺序：

1. 调 SDK 已有的 `get_qq_group_bot_state`（官方 `GET /v2/groups/{group_openid}/bot_state`）。读 `member_role`：`owner` / `admin` / `member`；顺带缓存 `allow_proactive_msg`。
2. 该接口文档写明 **11253 白名单**。失败则 `self_role` 保持未知，**不当管理员**，管理区不渲染。关键词 `无接口权限`。
3. 不靠「某条消息里自己像管理」猜测。事件里的 `member_role` 只填 `members` 表，不提升 `self_role`。

`self_role` 为 `admin` 或 `owner` 时，才开放官方文档里 **群管理员才能做、且 OlivOS 已封装** 的能力（不自己发明 HTTP）：

| 能力 | 官方约束 | SDK |
|---|---|---|
| 撤回他人消息 | 2 分钟；对象须为普通成员 | `delete_message` |
| @全体 | 管理员，每群每天 1 次 | Markdown `<qqbot-at-everyone />` |
| 看是否允许主动发言 | bot_state | 只读展示 |
| 禁言查询/设置 | 群管理 | `get/set_qq_group_restrict_chat_setting` |
| 入群申请看全部 / 审批 | 必须管理员；列表 30 QPM | 翻页拉空 `next_cursor`；`approve` / `decline` |
| 刷新官方成员列表 | 内邀，常 11253 | `get_qq_group_member_list`；失败保留事件缓存 |
| 群资料里的群名 | info 接口常 11253 | 有权限才回填 `display_name` |

踢人、黑名单等同属内邀/管理接口：管理区可以放入口，11253 或 `40062003` 按关键词失败，不假装成功。

非管理员：右栏不出现管理区；气泡菜单没有「撤别人」；@全体入口隐藏。


## 7. 撤回

官方：发出超过 **2 分钟**不可撤。管理员可撤普通成员消息（用事件 `d.id`）；普通成员只能撤自己的。SDK 对本进程发出的消息先做 120 秒校验，未知 id 仍交给平台。

控制台：

- 自己发的：2 分钟内显示撤回；超时灰掉，关键词 `撤回超时`（`40064004`）
- 别人的：**仅 `self_role` 为 admin/owner 时出现**；否则不显示。失败 `无撤回权限`（`40062003`）
- 成功：平台侧消失；本地 `recalled=1`，气泡改「已撤回」，**不删行**
- 频控 10 QPS，关键词 `撤回频控`

| `QQOfficialConsole_UploadAbort` | 写 | 删未完成的 temp |
| `QQOfficialConsole_Send` | 写 | 发送 |
| `QQOfficialConsole_Recall` | 写 | 撤回 |
| `QQOfficialConsole_SaveSettings` | 写 | 展示窗口等 |

`Send` payload 建议：

```json
{
  "bot_hash": "",
  "chat_type": "qq_group",
  "chat_id": "",
  "kind": "text|markdown|card",
  "text": "",
  "markdown": "",
  "card": {"type": "tuwen", "content": {}},
  "at": [{"id": "openid"} , {"id": "all"}],
  "quote_id": null,
  "images": [{"upload_id": "", "marker": "img_0"}],
  "force_active": false
}
```

`images` 只允许刚刚 `UploadBegin` 成功、尚未发送的 id。不要在 `Send` 里夹带 base64。Markdown 的 `marker` 与正文占位符对应，由前端生成，用户不填。`force_active=true` 仅调试：跳过被动池。默认 false。

回包统一：

```json
{
  "ok": true,
  "keyword": "成功",
  "error_code": null,
  "message_id": "",
  "ref_idx": null,
  "channel": "stream|passive|active",
  "pending_review": false
}
```

渲染用 `textContent` / 白名单 MD，禁止整包 `innerHTML`。

## 13. 风险

- WebUI = 控制台，能登录宿主就能对所有已知会话发言。不要公网裸奔。
- 主动发言依赖群主开关，失败 `主动无权限`。
- @全体每天每群 1 次且要管理员，误点成本高，必须确认框。
- 流式是插件自封装，SDK 升级后若官方加了同类接口，应改走 SDK、删插件内重复实现。
- 被动 `msg_seq` 内存与插件库可能不一致，以「换凭据 / 改主动」消化去重错误，不要本地盲加 seq 绕过 SDK。

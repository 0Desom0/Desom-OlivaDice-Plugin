# [OlivOS 插件] 获取主动授权 QQGroupAuthorize v1.2.9

- **名称**：获取主动授权 / QQGroupAuthorize
- **作者**：Desom-fu
- **版本**：1.2.9
- **适用平台**：QQ 官方机器人，OlivOS 的 qqGuildV2 / qqGuildv2_link 接入
- **适用场景**：QQ 群聊
- **前置插件**：OlivaDiceCore 可选，未安装也能使用
- **运行环境**：Python 3.11；使用支持本文所述 qqGuildV2 接口的青果主项目版本
- **操作系统**：适配 Windows、macOS、Linux；实际浏览器渲染已在 Windows 验证

## 插件简介

群主经常会问：机器人为什么只能收到 @ 它的消息？怎么让机器人接收群内全部消息、主动在群里发言？

这个插件会生成一张带操作标记的说明图，让群主按图找到 QQ 里的机器人设置。两条入口合并在同一张图里，显示当前机器人的名称、AppID 和头像。

当前版本提供：

- 群成员通过命令获取设置说明图。
- 可选的机器人自身入群自动发图，默认关闭，每个 bot 独立开关。
- 中英文命令与帮助，支持免空格输入。
- QQ 在线头像、当前 bot 下载缓存、用户 avatar 双层图片兜底，最后回退到名称首字。
- 白色界面、红框和红色圈号；机器人资料页保留 QQbot 背景，删除简介。
- 无损 PNG 缓存，正常情况下只发送一张图片。
- 图片渲染、缓存或上传失败时，改为发送文字步骤。

**本插件负责发送指引，实际权限由群主在 QQ 中设置。** 当前不发送授权跳转按钮，也不会替群主开启权限。群主完成设置后，机器人能否使用全部消息、主动消息能力，还取决于 QQ 平台与机器人接入端是否支持。

**仅限手机 QQ 9.2.90 及以上，电脑端目前不可用。版本低于 9.2.90 时，请群主先更新手机 QQ 再操作。** 图片顶部用加大红字突出要求，help 和文字降级同步说明；插件不读取或校验客户端版本，不添加自定义版本弹窗。

## 安装

1. 确认机器人使用 qqGuildV2 接入，并已能在目标 QQ 群收发消息。OneBot、QQ 频道、QQ 私聊不在本插件支持范围内。
2. 将 `QQGroupAuthorize.opk` 直接放入 OlivOS 的 `plugin/app/` 目录。
3. 按 OlivOS 已有的插件重载流程加载，或重启后加载。
4. 在 QQ 群里 @ 机器人发送 `.授权 全消息` 或 `.auth allmsg`。

OPK 已按 OlivOS 插件结构打包，包内运行文件直接在根层，无外包文件夹。无需先手动解压，也不要把运行文件拆散放进 `plugin/app/`。

插件没有桌面配置窗口、菜单或 WebUI。日常操作使用聊天命令，骰主名单和可选显示设置通过本地 JSON 配置。

### 浏览器与依赖

HTML 转图片需要本机已有的 Chrome、Edge、Chromium 等受支持浏览器。插件会自动查找常见安装位置，使用独立临时资料目录进行无界面截图，不打开可见浏览器窗口。

Python 运行依赖仅为 **OlivOS 已有的 Pillow 和 requests**，无需另装 Playwright、Selenium 或新的 Python 包。插件不会自动下载浏览器、安装字体或修改 PATH。

| 系统 | 浏览器查找位置 | 中文字体优先顺序 |
| --- | --- | --- |
| Windows | Program Files、Program Files (x86)、LocalAppData 中的常见目录 | 微软雅黑 / Microsoft YaHei → Microsoft YaHei UI → 黑体 |
| macOS | /Applications、~/Applications | 苹方 / PingFang SC → Heiti SC → Hiragino Sans GB |
| Linux | PATH 中的 Chromium、Chrome、Edge | Noto Sans CJK SC → WenQuanYi Micro Hei → Droid Sans Fallback |

会继续回退到系统 sans-serif。精简 Linux 系统需要自己已有中文字体，否则图片可能出现方框。Linux 以 root 运行时，截图进程使用 Chromium 所需的 `--no-sandbox`；页面只加载本地 HTML 和内嵌图片。

没有可用浏览器时，命令会改发文字指引，仍可让群主照步骤设置。

## 命令总览

根命令为中文 **授权**、英文 **auth**，前缀支持 **`.`、`/`、`。`**。下面的示例用空格排开方便阅读，实际输入可以省略空格，英文大小写不敏感。

| 功能 | 中文命令 | 英文命令 | 权限 |
| --- | --- | --- | --- |
| 获取设置说明图 | `.授权 全消息` | `.auth allmsg` | 任何群成员 |
| 查看帮助 | `.授权 帮助` | `.auth help` | 任何群成员 |
| 开启入群自动发图 | `.授权 入群 开` | `.auth join on` | 骰主 |
| 关闭入群自动发图 | `.授权 入群 关` | `.auth join off` | 骰主 |
| 查看当前 bot 开关 | `.授权 入群 状态` | `.auth join status` | 骰主 |

免空格示例：

```text
.授权全消息
/authallmsg
。授权帮助
.authhelp
.授权入群开
.authjoinon
.授权入群关
.authjoinoff
.授权入群状态
.authjoinstatus
```

`.授权` 或 `.auth` 单独输入会显示帮助；`.授权 入群` 或 `.auth join` 不带参数时查询当前开关。

入群参数可以使用 `开/on`、`关/off`、`状态/status`。中文根命令后用中文子命令，英文根命令后用英文子命令。

命令按关键词逐层匹配，不依赖空格分词。根命令、子命令和参数之间可以有空格或不写空格；不需要输入群号，也不能通过附加 bot 参数去操作其他机器人。

所有命令只在 QQ 群聊生效。发图命令不会改动任何权限；它只发送操作说明。帮助中包含中英文示例，并显示当前用户 ID，方便配置骰主。

## 群主如何设置

两条路线最终修改的是同样的两项权限，每群设置一次即可。

### 路线一：从群成员列表进入

1. 打开群成员列表，在「机器人」分组找到当前机器人。
2. 点击机器人进入资料页，再点右上角齿轮。
3. 将「机器人可获取的群聊消息范围」设为「获取群内全部消息」。
4. 打开「机器人主动在群聊内发言」开关。

### 路线二：群成员列表不好找时，从群机器人页面进入

**如果群成员列表不好找，也可以从群机器人页面进入。**

1. 在群聊消息页面点右上角菜单，进入「聊天信息」。
2. **群主点击「群机器人」**。
3. 找到当前机器人，点这一行最右侧的「管理」。
4. 将消息范围设为「获取群内全部消息」，打开主动发言开关。

图里的红框、圈号和提示标记会指出需要点击的位置。QQ 不同版本的界面可能略有差异；两条路线均应由群主操作。

## 入群自动发图

默认是 **关闭** 的。骰主可以在当前 bot 所在的任意 QQ 群执行：

```text
.授权 入群 开
```

英文对应：

```text
.auth join on
```

开启后，**这个 bot 新加入其他 QQ 群时**自动发送同一张设置图。该开关影响当前 bot 的所有群，其他 bot 不受影响，也不会给已加入的群批量补发。

关闭或查询：

```text
.授权 入群 关
.授权 入群 状态
```

```text
.auth join off
.auth join status
```

只在机器人自身入群时发送。普通群成员进群不会触发；重复的机器人入群通知会去重。

所有聊天命令的回复均 **引用这次命令消息，不 @ 发令者**。发图、help、开关操作结果、权限不足、错误提示和图片失败后的文字说明都采用相同方式；原消息 ID 仍用于被动回复。图片正文为空，不在图片后添加换行，不再发送第二条 Markdown。

入群自动发图使用 QQ 入群事件的回复凭据；没有命令发送者，所以不 @ 机器人自身、不伪造引用，仍只发送一张 PNG。图片发送失败时沿用相同规则发文字步骤。

本插件不拦截 Core 原来的入群欢迎和入群记录。如果 Core 本身已发欢迎词，两者都可能发送；关闭本插件的入群开关只停止设置图，不会改动 Core 欢迎词。

### 谁能操作这个开关？

权限取以下两类用户的并集：

- 安装并加载 OlivaDiceCore 时，当前 bot 在 Core 中配置的骰主。
- 本插件全局配置文件里的骰主。

未安装 Core 时，使用插件配置的骰主即可。QQ 群主、群管理员不会仅凭群身份获得入群开关权限；他们仍可发说明图命令，并由群主完成 QQ 权限设置。

## 骰主配置

首次加载后自动生成：

```text
plugin/data/QQGroupAuthorize/config.json
```

相对路径均以 OlivOS 的启动工作目录为基准。

文件结构示例：

```json
{
  "svn": 0,
  "browser_path": "",
  "masters": ["YOUR_GROUP_MEMBER_OPENID"],
  "bots": {
    "ACTUAL_BOT_HASH": {
      "name": "",
      "auto_join": false
    }
  }
}
```

`YOUR_GROUP_MEMBER_OPENID` 和 `ACTUAL_BOT_HASH` 是示例占位符，实际填写时请替换。

| 字段 | 说明 |
| --- | --- |
| svn | 插件自动管理的图片修订号，缺失时按 0 处理，图片生成并保存成功后更新 |
| browser_path | 全插件共用的浏览器绝对路径，空字符串表示自动查找 |
| masters | 全插件共用的骰主列表，填写用户 ID 字符串 |
| bots | 各 bot 的名称与开关配置，以实际 bot hash 为键 |
| name | 当前 bot 自动取得并保存的名字，获取失败时作为兜底 |
| auto_join | 是否在这个 bot 自身入群时自动发图，默认 false |

### 取得自己的用户 ID

在群内发送：

```text
.授权 帮助
```

或：

```text
.auth help
```

帮助末尾会显示「当前用户 ID / User ID」。复制它，作为字符串放进 `masters` 列表，例如：

```json
"masters": ["复制出来的用户ID"]
```

QQ 官方群消息里的 ID 通常是 **群成员 OpenID，并不是 QQ 号**。不要直接填 QQ 号来猜。不同机器人对应的用户 ID 可能不同，可以把所需 ID 全部加入同一个全局列表。

修改 `masters` 时保留文件里的 `bots` 和其他字段。配置按请求读取，保存有效 JSON 后下次命令即可使用，不需要为修改名单重新安装插件。

`masters` 全局生效，`auto_join` 按 bot 独立保存。Core 的 masterList 由 Core 管理，本插件只读取权限判断，不修改它；也不会因为 Core 主从账号关系而把多个 bot 的入群开关合并。

## 头像、显示名与图片缓存

资源统一放在：

```text
plugin/data/QQGroupAuthorize/
├── avatar.png                  # 用户的最终图片兜底
├── <bot_hash>.png              # 当前 bot 的下载头像缓存
├── authorization.png
├── authorization.cache.json
├── config.json
└── theme.json
```

### 头像优先级

1. 有 bot OpenID 时，通过 `https://q.qlogo.cn/qqapp/<AppID>/<OpenID>/0` 获取 QQ 在线头像。成功就保存到资源目录的 **`<bot_hash>.png`**，不创建子目录。
2. OpenID 缺失、下载失败或图片无效时，读取当前 bot hash 命名的已下载头像，这是第一层图片兜底。
3. 当前 bot 的缓存也不可用时，读取用户提供的 **`avatar.png`**，这是最终图片兜底。
4. 仍无有效头像时，取 bot 名称首字生成占位头像。

bot hash 头像和用户 avatar 支持同样的 png、jpg、jpeg、webp、gif、bmp 后缀，大小写均可。比如 `<bot_hash>.jpg`、`<bot_hash>.webp` 或 `avatar.jpeg` 都可以读取。新下载头像规范化为 PNG 后存成 `<bot_hash>.png`，不会把 PNG 内容伪装成其他格式；无效文件会继续查找其他后缀。

**用户 avatar 不会被在线头像覆盖。** 每个 bot 只更新以自己 hash 命名的头像文件，也不会读取别的 bot 缓存。新头像已取得但写入失败时，仍使用本次数据发图。

头像居中裁切为圆形显示，根据主要颜色设置页面主色；无头像时用常见随机色。页面裁切不会改变用户 avatar 文件。

AppID 取自 OlivOS 当前已加载 bot 配置，不需要手填。在线头像内存缓存一小时，失败冷却一分钟；再次成功获取时更新磁盘缓存，内容未变则不重复写盘。

### 名称和统一配置

所有配置统一在 **`config.json`**，不再使用独立的 settings.json，也不兼容或迁移旧配置字段。

bot 名称先取已加载 Core 的当前 bot 名称，再尝试 QQ 自身账号信息。只要取得有效名字就会写入 **`bots[bot_hash].name`**。取不到时才使用这个 bot 保存的名字，仍为空时显示带 AppID 的默认名。多个 bot 的名字各自独立，名字变化会更新缓存；默认生成的名字不会当成真实名称写入。

如果无法自动取得名称，可以编辑对应 bot 的兜底 name，例如：

```json
{
  "svn": 0,
  "browser_path": "",
  "masters": [],
  "bots": {
    "ACTUAL_BOT_HASH": {
      "name": "橘波特",
      "auto_join": false
    }
  }
}
```

此例仅说明结构；实际编辑请保留自己已有的 masters、其他 bot 和设置。手填 name 是兜底，之后成功取得名字时会被更新，不是强制显示名。

浏览器安装在特殊路径时，在同一个 config.json 的 **顶层 `browser_path`** 填写本机浏览器绝对路径。浏览器路径和 masters 共用，name 与 auto_join 按 bot hash 保存。Windows JSON 路径建议使用 `/`，或将反斜杠写成 `\\`。

已有 settings.json 不会再被读取或自动删除，其旧显示名不会迁移；需要的兜底名称请直接写到统一配置中。

### 图片清晰度和缓存

说明图是 **2340 × 3195 的无损 PNG**，把两条入口放在同一张图里。当前演示图约 570 KiB，实际体积会随头像和系统字体变化。

所有 bot 共用一张 `authorization.png`。缓存会核对当前 bot 名称、AppID、头像、颜色、HTML、字体和像素尺寸，匹配时直接发送，变化时重新生成。多 bot 交替触发时可能重新渲染，但不会因为共用目录直接发出上一台 bot 的图。

更新插件后，下一次需要发图时会检查 config.json 的 **svn**：缺少时按 0 读取，当前插件 svn 大于保存值时强制重新生成，即使页面内容没有变化。PNG 和缓存保存成功后写入当前插件 svn，之后恢复缓存复用。生成或缓存保存失败时保留旧修订号，下次继续重试；配置 svn 写入失败时仍发送本次已生成图片。请保留这个自动维护字段，不需要手动设成当前版本。

OPK 解包目录清理后不会导致模板丢失：HTML 在插件加载时读入内存，后续从内存渲染。截图和浏览器临时目录使用结束后清理，持久数据保留在资源目录。

## 常见问题

### 为什么发图命令没有反应？

先确认是 QQ 群聊、机器人使用 qqGuildV2 接入、插件已加载成功。机器人尚未接收全部消息时，请先 @ 它发送命令。支持 `.授权 全消息` / `.auth allmsg`，英文不再使用旧的 `.allmessage`。

发图与帮助命令不接收其他参数，不要再接群号。`.auth help` 是帮助入口，不是 `.auth allmsg help`。

### 群成员列表不好找怎么办？

走图片中的第二条路线：群聊右上角菜单 → 聊天信息 → 群机器人 → 当前机器人的「管理」。这条路线也由群主操作。

### 为什么没有「群主点此授权」按钮？

本版只保留手动设置指引。授权跳转入口需要真实群号、机器人 QQ 号及 UID 等数据，当前没有自动填充这些数据的实现；按钮入口已注释，不发送无效按钮或把开发文档链接当成授权地址。

### 提示「仅骰主可操作此开关」怎么办？

如果有 Core，请用当前 bot 配置的 Core 骰主身份发送；否则通过 `.auth help` 取得当前用户 ID，填进插件 `config.json` 的 `masters`。QQ 号、群主身份与插件骰主是不同的概念。

### 开了入群开关，为什么有人进群时没有发图？

只对机器人自身入群发图，普通成员进群不触发。开关不会给之前已经加入的群补发；可以手动发送发图命令。

如果确实是机器人新入群，请检查当前 bot 的开关，以及 OlivOS 是否收到 `GROUP_ADD_ROBOT` 事件和事件 ID。缺少事件凭据或 QQ 拒绝发送时，插件会记录原因，不改为无凭据的主动发送。

### 收到的是文字，不是图片？

这是降级指引，常见原因是没有受支持浏览器、截图失败、资源不可读、或图片上传失败。先看插件日志。缓存不可写时，只要图片已经生成成功，仍会直接从内存尝试发送。

### 怎么恢复默认行为或停止入群发图？

执行 `.授权 入群 关` / `.auth join off` 即可停止当前 bot 的入群图，手动发图和帮助继续可用。卸载本插件也不会自动撤销 QQ 群里已经设置的权限；修改权限仍由群主在 QQ 中操作。

## 验证与使用范围

已完成命令解析、权限并集、按 bot 开关、默认关闭、自身入群筛选与去重、事件回复、头像回退、PNG 缓存等离线测试。Windows 下实际生成并检查了图片，OPK 加载后清理解包 HTML 的场景也验证过。

macOS / Linux 的字体和浏览器查找已做离线核对，尚未实机运行。真实机器人入群自动发图还需在目标群验收；发送能否成功由 QQ 平台返回结果决定。

旧版生成的 WebP 或旧 bot 子目录不会自动删除。升级后使用新的共用 PNG 缓存即可。

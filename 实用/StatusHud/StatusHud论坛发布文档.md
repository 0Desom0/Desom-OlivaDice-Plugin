# 青果插件 · 骰点结果状态栏（StatusHud）

- **名称**：骰点结果状态栏 / StatusHud
- **作者**：Desom-fu
- **版本**：1.0.0
- **前置插件**：**OlivaDiceCore，必须安装并成功加载**
- **适用场景**：群聊骰点、私聊骰点、暗骰、代投及多人检定
- **管理方式**：聊天指令，无需 WebUI
- **运行环境**：按 OlivaDiceCore 3.5.1（svn 1201）、当前 OlivOS 接口及 Python 3.11 开发；其他版本需要核对兼容性
- **验证情况**：已完成基于本地 Core、OlivOS 与规则插件源码的离线功能回归，尚未连接实际机器人测试

---

## 插件简介

跑团时想在骰点结果里顺手看到角色的生命、理智、魔力等状态，可以使用这个插件。

**StatusHud 会把对应角色当前的 `sn` 文本用 `『』` 包住，放在骰点回复的第一行，随后留一行空白再接原来的结果。** 显示哪些属性，由你的人物卡模板和名片格式决定。

例如，当前 `sn` 内容为「艾琳 HP10/12 SAN55/99 MP8/10」，执行 `.ra 侦查` 后，回复形式如下：

```text
『艾琳 HP10/12 SAN55/99 MP8/10』

艾琳进行侦查检定：1D100=28/60，成功
```

以上为格式示意；实际骰点文本沿用 Core 或对应规则插件的回复设置。

支持的功能：

- **默认开启**，玩家可以单独开启或关闭自己的 HUD。
- 骰主可以调整全局默认，供没有手动设置过的玩家使用。
- 全局默认与个人开关都遵循 Core 的 **link 设置**。
- 一条指令骰多次，同一角色的 HUD 只在对应接收位置添加一次。
- **暗骰提示保持原样**，私聊结果和旁观者收到的结果显示 HUD。
- **代投显示被代投人的状态**，也按被代投人的开关判断。
- 多人合并结果可以逐行显示多个人的状态，每人各用一对 `『』` 包住。
- 已核对 `sh`、`tq`、`ms`、`ra`、`ta` 的真实骰点处理流程。

## 安装

1. 确认 OlivaDiceCore 已安装并正常加载。
2. 将 `StatusHud.opk` 放入 OlivOS 的 `plugin/app/` 目录。
3. 重载插件。
4. 发送 `.hud show` 查看状态，或发送 `.hud help` 查看帮助。
5. 使用已有的人物卡发送骰点指令，确认结果第一行显示当前状态。

也可以使用源码形式，将完整的 `StatusHud` 文件夹放入 `plugin/app/`。**OPK 与源码安装方式选择一种，避免重复加载。**

首次安装时全局默认开启，有人物卡且能生成有效 `sn` 的玩家可以直接使用。

插件默认优先级为 **19000**，先于 Core 的 **20000**。如果手动调整过插件优先级，请保持 StatusHud 的命令入口先于 Core。

## 命令总览

根命令为 **hud**，支持 **`.`、`。`、`/`** 三种前缀，英文大小写不敏感。群聊和私聊均可使用；消息接收仍遵循 Core 的群聊屏蔽及私聊开关。

| 指令 | 功能 | 权限 |
| --- | --- | --- |
| `.hud help` | 显示详细帮助 | 所有人 |
| `.hud on` | 为自己开启 HUD，保存个人设置 | 所有人 |
| `.hud off` | 为自己关闭 HUD，保存个人设置 | 所有人 |
| `.hud` | 切换自己当前的有效开关，并保存为个人设置 | 所有人 |
| `.hud show` | 查看有效开关、设置来源和全局默认 | 所有人 |
| `.hud global on` | 将全局默认设为开启 | 当前 bot 的 Core 骰主 |
| `.hud global off` | 将全局默认设为关闭 | 当前 bot 的 Core 骰主 |

命令参考轻量模板，采用贪婪匹配，支持省略关键字之间的空格：

```text
.hud on
.hud off
.hud show
.hud help
.hud global on
.hud global off
。hud on
/hud show
```

这些指令管理的是**操作者自己的开关**；在 `.hud on/off` 后面 @ 别人不会替对方修改设置。

## 个人设置与全局默认

**全局默认只影响没有手动设置过的用户。** 它不是强制关闭所有人的总开关。

| 个人设置 | 全局默认 | 实际状态 |
| --- | --- | --- |
| 未设置 | 开启 | 开启 |
| 未设置 | 关闭 | 关闭 |
| 手动开启 | 开启或关闭 | 开启 |
| 手动关闭 | 开启或关闭 | 关闭 |

例如：

- 小明执行过 `.hud on`，之后骰主执行 `.hud global off`，小明仍然开启。
- 小红执行过 `.hud off`，之后骰主执行 `.hud global on`，小红仍然关闭。
- 小白没有执行过个人设置指令，会随全局默认一起变化。

**直接发送 `.hud` 也算手动设置。** 它会将当前有效状态取反并保存，而不是临时切换一次。

`.hud show` 会显示当前状态来自「个人设置」还是「群链全局默认」。当前版本没有恢复跟随全局默认的聊天指令。

---

## 群链与多 bot

全局默认和个人开关都按 Core 的 link 关系读取。存在主从关联时，使用 Core 解析后的主 bot 数据目录；没有关联时，各 bot 使用自己的数据目录。

因此，在共享同一 link 数据目录的 bot 上修改个人开关或全局默认，会影响使用该目录的其他 bot。

**全局设置的权限仍按当前实际接收命令的 bot 判断。** 需要在这个 bot 的 Core 骰主名单中，群主或群管理员身份本身不能修改全局默认。

HUD 的开关共享不代表角色状态也相同：**不同群显示各自绑定的人物卡和群名片，私聊使用全局选中的人物卡和全局名片。**

## 什么情况下会显示 HUD？

判断依据是指令处理过程中是否实际调用了 **OlivaDiceCore OneDice 的 `roll()`**。

- 普通骰点、规则检定等调用过 `roll()` 的结果，会添加 HUD。
- 纯计算或骰点报错，只要已经调用过 `roll()`，也会按同样规则处理。
- 帮助、开关查询等没有调用 `roll()` 的指令，回复保持原样。
- 参数或权限检查在骰点前就失败、没有调用 `roll()` 时，提示保持原样。
- 对应用户关闭 HUD、没有当前人物卡或没有有效 `sn` 时，回复保持原样。

### 暗骰与私聊

暗骰在群内发送的「进行了暗骰」之类提示不添加 HUD。

发起人收到的私聊骰点结果，以及旁观者收到的结果，会添加 HUD；暗骰代投时显示被代投人的状态。结果发给谁，沿用原指令的发送规则。

直接在私聊里执行骰点指令，也支持显示 HUD。

### 代投

按 Core 或已核对规则插件实际确认的代投目标处理：

- HUD 内容取**被代投人**当前的 `sn`。
- HUD 开关取**被代投人**的个人设置或其全局默认。
- 发起人的 HUD 开关不影响被代投人的结果。

是否允许代投、谁能代投以及怎样指定目标，仍遵循原指令的规则。**消息里出现 @ 不一定代表代投**；例如普通 `.r` 中的 @ 不会被直接认定为代投目标。

### 多次骰点、分页与多人结果

一条指令中同一角色骰多次，或回复分成多页时，该角色的 HUD 只在每个接收位置的第一条对应结果中出现一次。发起人和不同旁观者仍各自收到带 HUD 的结果。

如果一条合并结果涉及多个人，各位开启 HUD 且有有效 `sn` 的角色，每人各用一对 `『』` 包住并独占一行。**条目之间一个换行，只有最后一条后接两个换行，再接原结果。** 只有一个人时，其状态后同样接两个换行：

```text
『艾琳 HP10/12 SAN55/99』
『贝克 HP7/11 SAN42/99』

原来的多人骰点结果……
```

如果规则插件逐个发送不同人的结果，则各人的 HUD 分别放在自己的第一条结果前。

## `sh / tq / ms / ra / ta` 支持情况

以下指令已使用本地插件真实处理流程进行离线回归验证：

| 指令 | 来源 | 验证用例 |
| --- | --- | --- |
| `sh` | OlivaDiceShouHun · 狩魂者 | `.sh 3#2`、`.shh 3#2` |
| `tq` | OlivaDiceSanchi · 三尺之下 | `.tq 3`、`.tqh 3`、多人合并结果 |
| `ms` | OlivaDiceMS · 母舰 | `.ms` |
| `ra` | OlivaDiceCore | `.ra 侦查`、`.rah 侦查` |
| `ta` | OlivaDiceTA · 三角机构 | `.ta 1` |

这五类指令的普通结果与代投结果均已覆盖；表中列出的暗骰还核对了群内提示、私聊结果及旁观者转发。

对应规则插件需要另行安装，并满足其模板、参数和使用条件。StatusHud 为已有骰点结果添加状态，本身不提供这些规则指令。

其他插件只要使用同一份 Core OneDice，并通过常规 OlivOS Event `reply/send` 发送结果，也能接入。自行实现代投且不提供可识别目标信息的插件，需要单独核对；这种情况下可能按消息发起人显示 HUD。

直接使用协议 SDK 发送、使用独立 OneDice 副本，或后台任务没有携带原事件与上下文的情况，暂不在当前接入范围内。

## `sn` 内容从哪里来？

显示内容遵循 Core 裸 `.sn` 的格式选择规则：

1. 当前群的名片记录。
2. 全局名片记录。
3. 当前人物卡模板的 `snTitle`。
4. default 模板的 `snTitle`。

具体回退条件沿用 Core 的 `.sn` 行为；选择到的格式为空时不显示 HUD。人物卡名、技能属性和 `SANMAX` 等占位符按当前卡的数据生成。

**不需要先手动执行一次 `.sn`。** 只要当前人物卡的模板能生成有效内容，就可以显示。想调整首行显示的属性，请使用 Core 原有的名片设置或修改人物卡模板。

HUD 读取的是发送结果时的当前人物卡数据，不会执行 `.sn` 命令或改动群名片。每个 `sn` 内部的换行会合并为空格，保证每个人的状态只占一行。

## 数据保存

数据目录：

```text
plugin/data/StatusHud/
└── {botHash}/
    ├── .lock
    ├── config.json
    └── user/
        └── {userHash}.json
```

`botHash` 是 Core link 解析后的共享 bot 标识，`userHash` 是 Core 根据用户 ID 和平台生成的用户标识。

全局配置 `config.json` 的初始内容：

```json
{
    "global_enabled": true
}
```

用户手动关闭后的个人文件示例：

```json
{
    "enabled": false
}
```

个人文件仅在手动设置时创建；文件不存在就视为未设置，跟随全局默认。设置保存后，重载插件仍然保留。

所有配置读写均有线程锁和操作系统文件锁保护，并通过临时文件与原子替换保存，避免并发覆盖。损坏的配置不会被默认值自动覆盖；HUD 读取失败时保留原来的骰点回复，设置操作失败时会提示检查日志。

日常使用推荐通过聊天指令调整设置。

## 常见问题

### 开着 HUD，为什么骰点没有状态栏？

先用 `.hud show` 确认有效开关，再检查当前群绑定或私聊选中的人物卡，确认其名片格式或模板能生成有效 `sn`。代投时要检查被代投人的设置和人物卡。

如果对应回复没有实际调用 Core OneDice，或使用了上述接入范围之外的发送方式，也不会添加 HUD。

### 全局关了，为什么有人还显示？

这个人有个人开启设置。全局默认只影响未手动设置的用户；个人设置优先。

### 我关了 HUD，为什么帮别人代投时仍然显示？

代投看被代投人的开关和状态。对方开启了 HUD，结果就会显示对方的 `sn`。

### 为什么同一个人在不同群显示的状态不一样？

各群可以绑定不同人物卡，也可以设置不同的群名片格式。开关遵循 link，共享开关的群仍然各自读取当前群的卡和名片。

### 升级 Core 或规则插件后需要注意什么？

本插件依据已核对的骰点、代投和暗骰处理流程接入。相关内部结构变化时需要重新验证兼容性；反馈问题时请附上 Core 与规则插件版本、使用的指令和实际表现。

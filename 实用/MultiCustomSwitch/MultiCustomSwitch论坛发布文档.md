# 青果插件 · 多自定义回复切换（MultiCustomSwitch）

- **名称**：多自定义回复切换 / MultiCustomSwitch
- **作者**：Desom-fu
- **版本**：1.0.1
- **前置插件**：**OlivaDiceCore，必须安装并成功加载**
- **适用场景**：群聊独立回复、当前 bot 的全局回复、私聊回复
- **管理入口**：独立 WebUI 页面、桌面 GUI
- **运行环境**：已验证 OlivaDiceCore 3.5.0 / 3.5.1 及当前 OlivOS 接口
- **验证情况**：Windows 本地测试及 D:\OlivOS 真实宿主 GUI/WebUI 验证；尚未连接实际机器人发送消息

## 插件简介

想让同一个骰子在不同群使用不同的回复风格，又不想每次都替换整份 Core 自定义回复？

本插件可以为每个 bot 保存多套回复，由群主或管理员在群内切换。骰主也可以设置当前 bot 的全局默认回复，供没有单独设置的群和私聊使用。

支持的功能：

- 每个群独立选择回复，保存后重载仍保留。
- 每个 bot 独立设置全局默认回复和开关。
- 内置 `1/default` 和 `2/smp`，方便使用原有回复或全默认回复。
- 按名称或序号切换，名称未精确匹配时提供模糊搜索候选。
- 独立 WebUI 和桌面 GUI，支持逐项编辑、搜索及已修改 / 未修改筛选。
- 从任意已有回复复制新建，支持改名和自定义序号。
- 本地 JSON 导入、导出，以及 JSON 链接下载导入。
- bot 之间、bot 与 unity 模板库之间互相导入。
- 同名导入提供「覆盖 / 创建为副本 / 取消导入」三个选项。
- 独立的自定义回复编写帮助，两个管理界面均可查看。

**default 与官方 OlivaDiceWebUI / OlivaDiceNativeGUI 共用原有回复数据。** 在本插件修改 default 后，官方面板刷新也会显示；在官方面板修改后，本插件刷新同样能看到。

## 安装

1. 确认 OlivaDiceCore 已安装并正常加载。
2. 将 `MultiCustomSwitch.opk` 放入 OlivOS 的 `plugin/app/` 目录。
3. 重载插件。
4. 在群内发送 `.mcs help` 查看帮助，或打开管理界面导入回复。

也可以使用源码文件夹形式，将 `MultiCustomSwitch` 文件夹放入 `plugin/app/`。

WebUI 需要宿主支持插件页面注册、消息桥及静态资源缓存。GUI 使用 Python 的 Tk 支持；无桌面或无 Tk 的环境可以使用 WebUI 和聊天指令。

插件不额外启动 Web 服务，不需要配置独立端口，也不需要安装 Node.js 或前端依赖。OlivaDiceWebUI / OlivaDiceNativeGUI 本身不是强制前置；本插件提供自己的管理入口。

## 命令总览

根命令为 **mcs**，前缀沿用 Core 的设置，通常为 **`.`、`/`、`。`**。下表用空格分隔以便阅读，实际输入支持省略空格，英文大小写不敏感。

| 指令 | 功能 | 权限 |
| --- | --- | --- |
| `.mcs [回复名或序号]` | 本群切换到对应回复 | 群主 / 群管理员 |
| `.mcs global [回复名或序号]` | 设置当前 bot 的全局默认回复 | 骰主 |
| `.mcs list` | 查看当前 bot 已加载的回复列表 | 所有人 |
| `.mcs show` 或 `.mcs` | 查看本群选择、开关及实际生效回复 | 所有人 |
| `.mcs on` / `.mcs off` | 开启 / 关闭本群的回复切换 | 群主 / 群管理员 |
| `.mcs global on` / `.mcs global off` | 开启 / 关闭当前 bot 的全局回复切换 | 骰主 |
| `.mcs help` | 显示指令帮助 | 所有人 |

本群切换、开关及状态查询需要在群内使用。私聊可使用 `list`、`help`，骰主也可以在私聊执行 `global` 指令。

群设置按群主 / 管理员身份判断，**骰主身份本身不会代替群管理权限**。全局设置按当前 bot 在 Core 中的骰主名单判断。

### 免空格输入

命令按前缀贪婪匹配，不要求关键字和参数之间有空格：

```text
.mcs3
.mcs温柔回复
.mcslist
.mcsshow
.mcsoff
.mcson
.mcsglobal2
.mcsglobal温柔回复
.mcsglobaloff
.mcsglobalon
```

`global` 会优先识别为全局子命令，`list`、`show`、`help`、`on`、`off` 等关键字也优先于同名回复。给回复命名时建议避开这些命令名称。

### 模糊匹配

先尝试精确名称匹配，未命中时使用 Core `.st set` 相同的模糊搜索方式，显示推荐候选，并等待用户在 30 秒内发送数字选择。

**候选列表中的编号仅用于这次搜索，不是 `.mcs list` 中的固定回复序号。** 直接输入回复序号时，以 `.mcs list` 显示的序号为准。

## 序号 1 和 2 分别是什么？

| 序号 | 名称 | 说明 | 是否可编辑 |
| --- | --- | --- | --- |
| 1 | default | Core 当前原有的自定义回复，与官方面板共用数据 | 可以，直接修改 Core 原有回复 |
| 2 | smp | Core 获取的全默认回复集合，Bot 名使用真实账号登录名 | 只读 |
| ≥3 | 自定义回复名 | 已加载到当前 bot 的回复 | 可以 |

`.mcs1` 是回到 **Core 原有自定义回复**，不是清空自定义回复或恢复源码默认文本。

`.mcs2` 是使用 **全默认回复**。smp 本身不能编辑或覆盖；需要修改时，可以从 smp 复制新建一套回复。

smp 的 Bot 名来自账号登录信息。登录接口暂时不可用时显示账号 ID，不使用三字母 `Bot` 作为占位名。

### 新回复如何分配序号？

新建或导入一套新回复时，取当前 bot **已有最大自定义序号 +1**，不会填补中间空缺。

例如已有 `1、2、3、7`，下一套回复自动分配 `8`；只有内置 `1、2` 时，第一套自定义回复为 `3`。

- 创建时自动分配，之后可通过「改序号」调整。
- 同一个 bot 内序号不能重复，自定义序号必须是 ≥3 的整数。
- 不同 bot 可以使用相同序号，各自独立。
- 同名导入选择「覆盖」时，保留原序号及群引用。
- 同名导入选择「创建为副本」时，分配新序号。
- unity 模板本身没有序号，加载到 bot 后才分配。

## 全局与群设置如何生效？

**这里的“全局”只指当前 bot，不会修改其他 bot。**

首先检查全局开关，再检查群开关；两个开关都开启时，才使用选定的回复。

| 情况 | 实际使用的回复 |
| --- | --- |
| 全局关闭 | 所有群及私聊都使用 1/default，即 Core 原有回复 |
| 全局开启，本群关闭 | 本群使用 1/default |
| 全局开启，本群开启，已有单独群设置 | 使用本群选中的回复 |
| 全局开启，本群没有单独设置 | 使用当前全局默认回复 |
| 全局开启，私聊 | 使用当前全局默认回复 |

关闭开关会保留之前选中的回复。重新开启全局开关后，继续读取各群自己的配置；**不会把之前关闭的群也一并开启**。

### 新群的默认设置

首次安装时，全局默认开启，回复序号为 `1/default`。新群或没有单独设置过的群，群开关默认开启，并继承当前全局回复。

第一次执行本群切换或本群 `on/off` 时，会创建这个群的独立配置，记录当时的回复序号和群开关。之后调整全局默认回复，不会覆盖这个群的选择。

**本插件不遵循 OlivaDiceCore 的群链。** 即使两个群在 Core 中已关联，各群的回复选择与开关仍独立，不沿群链同步或继承。没有单独设置的群继承当前 bot 的全局设置。

例如，A 群已经选了「温柔回复」，B 群没有单独设置。骰主执行：

```text
.mcsglobal2
```

A 群继续使用「温柔回复」，B 群、新加入且未单独设置的群，以及私聊使用 `2/smp`。

再执行：

```text
.mcsglobaloff
```

所有群和私聊都恢复 Core 原有回复。之后执行 `.mcsglobalon`，A 群恢复自己的选择，其余未单独设置的群和私聊恢复使用全局选择。

## WebUI / GUI 使用

### 入口

- **WebUI**：登录 OlivOS WebUI，在侧栏「插件页面」打开「多自定义回复切换」的「回复管理」。
- **GUI**：在 OlivOS 托盘插件菜单中打开「多自定义回复切换」。

WebUI 应从宿主侧栏打开，直接双击 HTML 文件无法使用消息桥进行管理。

### 回复库

顶部「回复库」可以选择 **unity 模板库** 或某个 **bot**。

unity 只用于存放共享模板，**不会因为模板放进 unity，就自动出现在各 bot 的 `.mcs list` 中**。需要先加载到指定 bot。

从 unity 加载到 bot：

1. 选择目标 bot 的回复库。
2. 点击「从其他库导入」。
3. 来源回复库选择 unity，再选择对应模板。
4. 填写目标回复名并导入。
5. 在群内用 `.mcs list` 查看新回复的序号，再切换使用。

从 bot 导出到 unity 时，反过来选择 unity 为当前回复库、bot 为来源即可。不同 bot 之间也可以按相同方式导入。

### 新建与编辑

「新建复制」可以从 default、smp、当前回复或任意其他回复复制，不创建无来源的空模板。

选择回复后，可以搜索回复键、内容或说明，并按「全部 / 已修改 / 未修改」筛选。选中回复项后，在右侧编辑文本并保存。

- **已修改 / 未修改**：当前文本是否与所选恢复模块的默认文本一致。
- **未保存**：编辑框内还有尚未保存的改动。
- **恢复默认**：将当前回复项恢复为所选恢复模块的默认文本。
- **新增回复键 / 删除自定义键**：管理额外回复项；内置回复键不能直接删除。

其他窗口或官方面板已经修改同一套回复时，保存会提示刷新，避免旧内容直接覆盖新修改。

### 改名与改序号

改名会同步重命名回复 JSON 文件及列表记录，保留原序号，不改变各群指向的回复。

同一个文件夹内不允许重名，Windows 下仅大小写不同也按同名处理。

「改序号」可以一次调整多套回复，或交换两个回复的序号。保存时会同步修正当前 bot 的全局默认序号及全部群配置，让原来使用某套回复的群继续使用那一套。

### 恢复模块

bot 的「恢复模块」与 Core / 官方面板使用 **同一份 recover_model.json**，不会另存一份独立设置。修改后，官方面板刷新即可读取到。

unity 可以选择某个 bot 的恢复模块作为编辑比较基线；不选择时，使用 Core 获取的完整默认回复集合。

恢复模块影响编辑界面的默认比较和恢复操作，**不会把 smp 改成某个 bot 当前自定义的文本**。

## 导入、下载与重名处理

两个界面均支持：

- 从本地 JSON 文件导入。
- 输入 HTTP / HTTPS JSON 下载链接，下载并校验后导入。
- 将完整回复导出为 JSON。
- 从另一个 bot 或 unity 导入。

没有绑定在线回复库，下载时直接填写自定义回复 JSON 的链接。下载内容必须符合回复结构；网页、数组或包含非字符串回复内容的 JSON 会被拒绝。

出现同名时，选择：

| 选项 | 行为 |
| --- | --- |
| 覆盖 | 替换同名回复内容；bot 内保留原序号和群引用 |
| 创建为副本 | 创建新的副本名称；bot 内分配新序号 |
| 取消导入 | 保留原内容，结束这次导入 |

导入名为 `default` 的回复并选择覆盖，会直接修改 Core 原有回复。导入名为 `smp` 的回复也会显示重名选项，但覆盖会被拒绝，因为 smp 是只读的；请选择创建为副本或取消。

unity 没有内置序号，可以保存名为 default 或 smp 的普通模板。

## 自定义回复格式

沿用 Core 的回复 JSON 格式：回复键对应字符串。例如：

```json
{
    "strBotName": "青果",
    "strRoll": "{tName} 掷出了 {tRollResult}"
}
```

文件没有包含的回复键，从 **smp 全默认回复**补齐，不会从 `1/default` 的自定义内容补齐。`{}` 也是有效的回复文件，表示全部采用默认文本。

模板变量、随机回复分隔符 `|`、`{OR}` / `{DEVIDE}` 和牌堆引用等，继续由 Core 处理。具体变量请查看对应回复项说明及管理界面的「编写帮助」。

导出得到完整生效文本，可以用于其他 bot、unity 或官方面板导入。外部文件上限为 8 MiB；最多 5000 个回复项，单项文本不超过 20000 字。

## 数据目录

插件数据自动生成在：

```text
plugin/data/MultiCustomSwitch/
├── unity/
│   ├── 共享回复A.json
│   └── 共享回复B.json
├── <bot_hash_1>/
│   ├── config.json
│   ├── custom_list.json
│   ├── 温柔回复.json
│   ├── 简洁回复.json
│   └── group/
│       ├── <group_hash_1>.json
│       └── <group_hash_2>.json
└── <bot_hash_2>/
    ├── config.json
    ├── custom_list.json
    └── group/
```

`config.json` 保存当前 bot 的全局默认回复和开关：

```json
{
    "reply_model": 1,
    "enabled": true
}
```

群文件使用相同字段，保存本群的回复序号和独立开关。

`custom_list.json` 保存自定义序号与回复名的对应关系，不记录内置的 1、2：

```json
{
    "3": "温柔回复",
    "7": "简洁回复"
}
```

default 和恢复模块直接使用 Core 的原文件：

```text
plugin/data/OlivaDice/<bot_hash>/console/customReply.json
plugin/data/OlivaDice/<bot_hash>/console/recover_model.json
```

日常建议通过界面管理。手工编辑文件后，点击「刷新文件」重新加载；尤其是更改序号，请通过「改序号」同步修正群引用，不要只改列表文件。

## 常见问题

### unity 里有模板，为什么群里切换不到？

unity 只存模板。先将它导入当前 bot，再用 `.mcs list` 查看。其他 bot 已加载的回复也不会自动供当前 bot 使用。

### 全局切换之后，有的群还是原来的回复？

全局切换只影响没有单独群设置的群和私聊。已经单独设置的群保留自己的选择，这是正常行为。

### 全局关了，本群 on 为什么还是没有变化？

全局开关优先。全局关闭时，所有群都使用 Core 原有回复；本群 `on` 会保存群开关，但要等全局也开启后才生效。

### 本群 off 是不再发消息吗？

不是。`.mcsoff` 只让本群恢复使用 Core 原有回复，不会关闭骰子本身，也不会删除本群之前选中的回复。

### 修改 default 会不会影响官方面板？

会。default 就是 Core 原有自定义回复，两边共用数据，刷新即可看到。若只想修改某套独立风格，请先复制新建，再编辑副本。

### 自定义文件没有写全所有回复，会用什么补齐？

缺失的键使用 smp 全默认文本。不会混入 default 中已有的自定义文本。

### 回复文件损坏或丢失怎么办？

列表会标记该回复不可用，原来指向它的场景暂时使用 Core 原有回复。修复文件后刷新，再用 `.mcs show` 检查实际生效回复。

### 怎么临时停止本插件的回复切换？

骰主执行 `.mcsglobaloff`，当前 bot 的所有群和私聊就恢复 Core 原有回复；各群设置仍保留。之后执行 `.mcsglobalon` 即可按原设置继续使用。

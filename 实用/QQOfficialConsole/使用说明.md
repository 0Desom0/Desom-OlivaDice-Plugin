# QQ 官方机器人控制台

## 部署

将 `QQOfficialConsole/` 放入 OlivOS 的 `plugin/app/`；也可把目录**内部**的文件打包为 ZIP 并改扩展名为 `.opk`，包根目录必须直接包含 `app.json`、`__init__.py`、Python 模块及 `webui/index.html`。需要支持插件 WebUI 和当前 `qqGuildv2_link` SDK 的 OlivOS；仅从宿主侧栏「插件页面」打开，直接打开页面不具备消息桥。`app.json` 为 UTF-8 无 BOM，部署前检查开头不是 `EF BB BF`。

WebUI 登录者可向机器人能访问的会话发言及执行其有权限的操作；请保护宿主访问地址，不要将未受保护的控制台暴露到公网。插件不向网页提供机器人凭据，也不额外监听网络端口。

## 使用与数据

- 群聊和单聊显示在同一会话列表，头像与副标题分别缩写标记「群」和「单」；完整的 group_openid / user_openid 显示在副标题。没有官方群/好友列表时，可手动添加 openid，事件也会自动建立会话。
- 会话列表上方有「群」「单」两个筛选按钮，默认全开：点一下临时收起对应类型的会话，再点恢复。收起只是不显示——顶部机器人下拉里的未读总数与 @我 数只统计还在显示的会话，消息本身照常接收、入库、提醒，重新打开页面恢复全开。
- 首次打开只加载最近 30 条，向上滚动可加载更早消息。消息区的 `↑` 先滚到当前已加载消息的顶部，到顶部后再次点击可加载并显示更早一页，没有更早消息时提示「已经是最早的消息」；`↓` 直接重新加载并回到最新 30 条。停留在旧消息窗口时收到新消息，页面提示一次「收到新消息，点击 ↓ 回到最新」，不会强行把你拉回底部。消息列表顶部的「加载更早消息」按钮在已到达最早一条后自动隐藏。切走后的已加载内容缓存 30 分钟，切回默认显示最新位置并增量获取新消息。缓存为临时磁盘数据，和永久消息库分开；不设总容量上限，磁盘空间不足时会提示且保留当前会话。缓存较多时请留意可用磁盘空间。
- 发送失败（含平台判定内容过长、审核拒绝、频控等）时，会撤掉聊天区里那条「发送中」的占位气泡，正文、卡片字段和引用原样留在输入框；已上传的图片会在下次点发送时用原始文件自动重新上传，不需要重新选图。发送成功才清空输入框。
- 撤回入口只在群聊出现（官方没有单聊撤回接口，单聊的消息菜单里不提供撤回）；群聊里自己发的消息撤回后，气泡显示「已撤回」和蓝色「重新编辑」，点一下就把原文放回输入框（卡片会还原标题/描述/链接/配图地址）；别人的撤回消息只显示「已撤回」。⚙「消息显示（全部机器人）」里可开「防撤回」：开启后撤回的消息仍显示原文，默认关闭。
- 自己发出的消息作者名显示机器人真实昵称（`GET /users/@me` 的 `username`，失败时回退「机器人」），机器人下拉里也显示这个名字。
- 平台明确投递的群 @ 机器人消息会显示会话和账号角标，页面可见时提示；是否开启全量消息都适用。仅收到无法判断是否 @ 的全量消息时不猜测。进入会话即清除该会话全部未读与 @ 提醒并定位到最新消息，往上翻才是历史；标题栏「@我」按钮只在还有未读提及时出现，点击定位最早未读提及（目标后不超过 300 条时加载连续上下文，否则只加载目标附近并可向下分页）。
- @ 全体成员（`<qqbot-at-everyone />` 或 mentions 里的 all/everyone）在正文里显示为「at全体成员」，并计入该会话的提及角标；最后一次提及的类型决定角标文案（@我 / at全体成员）。同时 @ 到机器人与全体时，弹窗提示统一为「有人at全体成员」。⚙ 设置里可分别关闭「有人 @ 我」和「有人 @ 全体成员」的弹窗提醒（全局设置，对所有机器人生效）。两个开关互相独立：@全体 提醒关掉后，同时也 @ 到机器人的消息仍会按「有人@了我」提示；只 @全体、没 @ 到机器人的消息则完全不提醒。
- 右键群聊会话可置顶、修改备注、屏蔽本群、从列表隐藏、复制 ID。屏蔽后该群消息整体变灰（列表行与消息气泡），新消息照常入库显示，但不计未读、不计提及、不弹 @ 提醒，也不会把隐藏的会话顶回列表；取消屏蔽即恢复。屏蔽与置顶、隐藏一样只改本地标记，不影响 QQ 群本身。
- 机器人被拉入群时按入群时间排队获取官方群名（`GET /v2/groups/{group_openid}/info`）；撞限流自动退避，队首冷却时不越过它，限流任务不设重试次数上限；无接口权限（11253 等）标记失败不再重试，保留已有显示名。会话资料页可手动刷新单个群名（**不需要机器人是管理员 / 群主**，只需官方群信息接口的白名单，无权限会回 11253）；启动时自动为还没有群名的群补排队。点开还没显示群名/昵称的会话会自动补一次：群聊加入原来的排队队列（已在队列里不重复入队），单聊没有官方昵称接口，改为跨会话查成员缓存里这个人最近用过的昵称，查到就落库，查不到等之后的事件把昵称带进来、下次点开再查。群名与备注分开保存，列表标题优先显示备注。
- ⌕ 全局搜索同时搜会话和消息：会话按群名 / 单聊名 / 备注 / openid 匹配（单聊没有昵称接口时，会先用成员缓存补一次显示名再匹配；名称完全命中的排在前面），消息扫各会话库（每群最多 20 条、全程上限 100 条）。结果分「会话 N / 消息 N」两组，顶部有全部 / 群聊 / 单聊 / 消息范围筛选（只切换显示，不重复搜索）；点会话结果直接定位到对应群聊 / 单聊（被「群 / 单」筛选挡住时会自动恢复并在列表里短暂高亮），消息结果点进去切会话并定位到那条消息。左栏「使用说明」折叠面板可在 ⚙ →「界面（全部机器人）」里关掉（`show_help`，默认开）。
- 消息按账号、会话分别保存在 `plugin/data/QQOfficialConsole/<bot_hash>/msg/qq_group/<safe_id>.sqlite3`（群）或 `.../msg/qq_private/<safe_id>.sqlite3`（单聊）。`messages` 是该会话的消息，`members` 是该会话见过的人员，`passive_tokens` 是该会话的回复凭据，`join_requests` 是该群入群申请缓存；会话列表和群/单聊类型在该账号 `meta.sqlite3` 的 `chats` 表，跨账号设置位于 `global.sqlite3`。聊天记录默认保留 30 天，每小时自动清理一次，修改设置时立即按新期限清理；在 ⚙ 里把「聊天记录保留」设为 0 可永久保留（会持续占用磁盘，需要自己清理）。隐藏会话或撤回不会立即删除历史；但**保留策略到期会真的删数据库行**：按 `created_at` 对每个会话执行 `DELETE FROM messages`，隐藏会话和已撤回的消息超期同样会被删，随后重算该会话的未读 / 提及 / 最后预览。不会删 `.sqlite3` 文件本身，也不动 `chats` / `members` / `join_requests` 等其它表；SQLite 删行后文件不会自动变小（无 `VACUUM`，空间由后续消息复用）。设为 0 则完全跳过清理。请按常规备份整个数据目录及 SQLite WAL 文件。
- 普通消息图片只能通过文件选择器上传，不接受图片网址。发送材料暂存于 `plugin/data/image/temp/QQOfficialConsole/`，发送流程结束后删除；已上传但未发送的残留会按时间清理。图片进入发送流程时另存副本至 `plugin/data/QQOfficialConsole/sent-images/`，即使平台发送失败也可从该消息查看；在校验阶段失败而未进入发送流程的图片不会保存。默认保留 30 天，可设置为 0–3650 天（0 = 永久保留）；启动、每小时及修改设置时清理过期副本，读取时也会拒绝并清理过期副本，缩短期限立即生效。图片清理不删除消息记录、原始文件或永久表情（聊天记录到期清理由 `message_retention_days` 单独负责）。永久表情位于 `plugin/data/image/QQOfficialConsole/emoji/`，分机器人专属与全局，可上传、重命名、删除并插入消息；发送仅消费临时副本。
- 接收图片由插件服务端代下载（带机器人鉴权、仅限 QQ 多媒体域名、落盘 `plugin/data/QQOfficialConsole/inbound-images/`、同一张图只下载一次），再经消息桥分片回传，前端拼 `blob:` 显示；浏览器不直连图片地址。链接过期（rkey 失效）、下载失败或非图片内容时显示失败提示。卡片图片仍由浏览器直接访问 HTTPS 图片地址，图片站可看到访问者 IP。
- 群优先使用未过期被动凭据；单聊文本/Markdown 优先流式。主动发送、管理员操作、Markdown、撤回和入群申请仍受 QQ 官方账号权限与频率限制。流式请求发生网络超时后结果可能未知，不会自动重发以免重复。
- Markdown 引用会转换为正文顶部的作者和摘要引用块。其余可用原生引用的消息需有平台引用索引。QQ 官方机器人没有正文长度上限，插件不再做 3000 字拦截，输入框只显示「当前 N 字」；是否超长由平台判定（平台返回过长错误时回「消息过长」等关键词）。

## 图片桥接口

- `QQOfficialConsole_Bootstrap` 返回的全局 `settings` 里，`image_retention_days` 与 `message_retention_days` 默认都是 30；使用 `QQOfficialConsole_SaveSettings` 的 `settings` 对象设置整数天数（0–3650，0 表示永久保留，不自动清理）。保存 `message_retention_days` 时会立即按新期限清理一次超期聊天记录，之后每小时清理一次。`notify_mention` 与 `notify_everyone` 默认均为 `true`，设为 `false` 分别关闭「有人 @ 我」「有人 @ 全体成员」的弹窗提醒；`show_help` 默认 `true`，设为 `false` 隐藏左栏「使用说明」折叠面板；`anti_recall` 默认 `false`，设为 `true` 后撤回的消息仍显示原文（这几个开关都只接受布尔值）。`QQOfficialConsole_BotSelf` 返回当前机器人的 `name` 与 `avatar`（官方 `/users/@me`，成功缓存 1 小时）。`QQOfficialConsole_ChatAction` 的 `action` 支持 `pin` / `hide` / `mute`（`value` 为布尔，`mute` 即屏蔽本群）。`QQOfficialConsole_Admin` 的 `action` 支持 `restrict_query` / `restrict_set` / `kick`（`kick` 需要 `member_openid`，可选 `add_to_member_blacklist`，服务端校验管理员身份）。注意 `kick` 走官方 `batch_remove_members`，**该接口目前是内邀白名单能力**：未开通的机器人即使身为管理员也会回 `无接口权限`（11253），失败时不会清本地成员缓存。
- `QQOfficialConsole_Send` 返回 `local_id` 和 `images` 数组；`PullMessages` 中对应消息的 `content_json` 是 JSON 字符串，其 `images` 与发送响应相同，每项为 `image_id`、`marker`（Markdown 图片标记，普通图片为 null）、`mime`、`size`。仅实际进入发送流程并成功保存的图片有条目；发送失败不代表图片不可查看。
- `QQOfficialConsole_MessageImageRead` 请求 `bot_hash`、`chat_type`、`chat_id`、本地消息整数 `message_id`、`image_id` 和从 0 开始的整数 `index`（省略时为 0）。成功返回 `ok`、`keyword`、`image_id`、`index`、`total_chunks`、`size`、`mime`、`data_b64`，单片最多 256 KiB；各片解码后按顺序拼接。只允许读取指定账号和会话中对应发送消息的图片；过期、不存在或无权访问返回失败，不提供服务器文件路径。收到的外部图片不通过该接口读取。

## 已知平台及宿主限制

原生图文卡片要求填写 HTTPS 跳转链接及 HTTPS 图片地址；图片地址须由 QQ 平台能够访问。群聊优先使用被动凭据，单聊通过普通消息接口发送。实际可用性与内容审核由 QQ 平台决定。参考 [群聊发送接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)。
卡片图片由浏览器直接访问 HTTPS 图片地址，图片站可看到访问者 IP；宿主的插件页面 CSP 因此允许 HTTPS 图片，其他插件页面也受此策略影响。旧版宿主未放行时只能打开图片链接。群聊标题中的人数来自事件或刷新得到的成员缓存，并非官方全量人数。

本次同步修改的 OlivOS 宿主在移动端使用独立插件视口和「返回导航」，随 `visualViewport` 调整高度；已用浏览器模拟视口缩小验证。真实手机键盘和浏览器行为尚需真机验证，旧版宿主仍可能遮挡输入区。

# Lanota 新版计分与 Rating 公式推导

> 推导日期：2026-08-01  
> Portal 样本：当前账号的 Best 30、Recent 15、全谱面成绩及若干单曲详情  
> 结论等级：分数、谱面满 Rating、非满分 Single Rating、`ratingPercent`、B30/R5 均为高置信结论。非满分公式已通过同谱面控分实验，并逐项命中当前 44 条不重复的 B30/R15 记录。

## 已知分数、总物量、定数时的直接计算公式

已知：

```text
S = 新版整数分数，范围 0～1,000,000
N = 谱面总物量
C = 谱面官方定数
```

第一步，还原整数 EX 和精确分数准度 `x`：

```text
EX = ceil(2NS / 1,000,000)
x = EX / (2N)
```

只使用整数运算时：

```text
EX = (2NS + 999,999) // 1,000,000
```

必须校验输入是否互相匹配：

```text
floor(1,000,000 * EX / (2N)) == S
```

若校验失败，说明分数并非新版分数，或总物量、谱面版本至少有一项不正确。

第二步，根据定数计算基础 Rating `B` 与理论满值 `M`：

```text
当 C <= 15：
  B = C
  M = C + 1.5

当 C > 15：
  B = 1.5C - 7.5
  M = 1.5C - 6
```

第三步，根据精确准度 `x` 计算未截断的 Single Rating `R`：

```text
当 0 <= x < 0.90：
  R = (B + 1)x

当 0.90 <= x < 0.95：
  R = (B + 7)x - 5.40

当 0.95 <= x < 0.98：
  R = (B + 4)x - 2.55

当 0.98 <= x < 0.99：
  R = (B + 6)x - 4.51

当 0.99 <= x <= 1：
  R = (B + 7)x - 5.50
```

最终结果：

```text
精确 Single Rating = max(0, R)
显示 Single Rating = floor(精确 Single Rating * 100) / 100

精确 ratingPercent = 精确 Single Rating / M * 100
显示 ratingPercent = floor(精确 ratingPercent * 100) / 100
```

`Single Rating` 和 `ratingPercent` 必须从未截断的 `R` 分别计算、分别截断，不能先把 Single Rating 截成两位小数再反推百分比。正常定义域内只有 `x = 0` 时精确 Single Rating 才为 `0`；极小的正数可能因两位小数截断而显示成 `0.00`。

## 1. 先给结论

设：

- `H` = Harmony 数量
- `T` = Tune 数量
- `F` = Fail 数量
- `N = H + T + F` = 总物量
- `C = level + levelFraction / 10` = Portal 官方谱面定数

### 1.1 新版分数

```text
EX = 2H + T
MaxEX = 2N
Score = floor(1,000,000 * EX / MaxEX)
      = floor(1,000,000 * (H + T/2) / N)
```

也就是说：

- Harmony 按 1 个完整音符计分；
- Tune 按半个 Harmony 计分；
- Fail 不得分；
- 最后整体向下取整到整数分；
- 新版分数中没有连击分。

单个判定相对 Harmony 的扣分为：

```text
1 Tune 扣分 = 500,000 / N
1 Fail 扣分 = 1,000,000 / N
```

所以 Tune 或 Fail **没有跨谱面固定的扣分值**，谱面物量越大，每个判定扣得越少；一个 Fail 的扣分正好是一个 Tune 的两倍。由于总分最后向下取整，实际整数差可能受小数累计影响 1 分。

### 1.2 谱面理论满 Single Rating

按当前 Portal 数据，满分时的单曲 Rating 上限 `M(C)` 是：

```text
当 C <= 15.0：M(C) = C + 1.5
当 C >  15.0：M(C) = 1.5C - 6
```

两段在 `C = 15.0` 时都等于 `16.50`，因此是连续的。

### 1.3 实际 Single Rating

先定义精确分数准度 `x`：

```text
x = EX / MaxEX
  = (2H + T) / (2N)
  = (H + T/2) / N
```

再定义基础 Rating `B(C)`。它总是比理论满值少 `1.5`：

```text
B(C) = M(C) - 1.5

当 C <= 15.0：B(C) = C
当 C >  15.0：B(C) = 1.5C - 7.5
```

分数奖励 `Q(x)` 是连续的五段线性函数：

```text
当 0 <= x < 0.90：  Q(x) = x
当 0.90 <= x < 0.95：Q(x) = 7x - 5.40
当 0.95 <= x < 0.98：Q(x) = 4x - 2.55
当 0.98 <= x < 0.99：Q(x) = 6x - 4.51
当 0.99 <= x <= 1： Q(x) = 7x - 5.50
```

五个关键点为：

```text
Q(0.00) = 0.00
Q(0.90) = 0.90
Q(0.95) = 1.25
Q(0.98) = 1.37
Q(0.99) = 1.43
Q(1.00) = 1.50
```

实际单曲 Rating 和官网比率为：

```text
RawSingleRating = B(C) * x + Q(x)
SingleRating = max(0, RawSingleRating)
ratingPercent = SingleRating / M(C) * 100
```

把 `B(C)x` 与 `Q(x)` 合并后，也可以直接写成完整的单曲 Rating 分段式：

```text
当 0 <= x < 0.90：
  RawSingleRating = (B(C) + 1)x

当 0.90 <= x < 0.95：
  RawSingleRating = (B(C) + 7)x - 5.40

当 0.95 <= x < 0.98：
  RawSingleRating = (B(C) + 4)x - 2.55

当 0.98 <= x < 0.99：
  RawSingleRating = (B(C) + 6)x - 4.51

当 0.99 <= x <= 1：
  RawSingleRating = (B(C) + 7)x - 5.50

最终：
  SingleRating = max(0, RawSingleRating)
```

这里的 `Q(x)` 是分数奖励/修正项，不是最终 Rating。最低段中 `Q(x) = x`，所以：

```text
当 0 <= x < 0.90：
SingleRating = (B(C) + 1)x
```

由于当前所有谱面的 `B(C) + 1` 都为正数，所以只有 `x = 0` 时 Single Rating 才等于 `0`；不存在此前错误外推得到的中途归零点。`max(0, ...)` 仍可作为实现保护，但正常定义域 `0 <= x <= 1` 内的五段公式本身不会产生负数。

满分时 `x = 1`、`Q(1) = 1.5`，因此：

```text
SingleRating = B(C) + 1.5 = M(C)
```

反过来，由官网比率换算单曲 Rating：

```text
SingleRating = M(C) * ratingPercent / 100
```

Portal 的 `singleRating` 和 `ratingPercent` 是从各自未截断的计算值**分别向下截断到两位小数**，不是普通四舍五入。因此使用页面上已经截断的 `ratingPercent` 回算时，末位可能与页面 `singleRating` 相差 `0.01`。

### 1.4 B30、Recent 15 与 R5

```text
B30贡献 = Best 30 的 30 个 SingleRating 之和 / 35
R5贡献  = 最近 15 次游玩中最高的 5 个 SingleRating 之和 / 35
总Rating = B30贡献 + R5贡献
```

因此：

- 官网的 `Best 30: 15.05` 一类数字是对总 Rating 的贡献，不是 B30 的普通平均值；
- 官网栏目叫 `Recent 15`，因为候选池是最近 15 次游玩；
- 实际参与计算的只有其中最高 5 次，所以习惯上仍可称为 R5；
- R5 允许同一张谱面重复出现，当前实测 Recent 中同一首歌可出现多次；
- B30 与 R5 都除以 35，不是 B30 除以 30、R5 除以 5。

## 2. 新版分数逐例验算

### 2.1 Poppy：1497-1-1

本地当前 Master 物量为 `1499`：

```text
Score = floor((1497 + 1/2) / 1499 * 1,000,000)
      = floor(998999.3328...)
      = 998999
```

与给出的 `998999` 完全一致。

### 2.2 Poppy：一 Tune、零 Fail 的 `999666`

若总物量仍是 `1499`，一 Tune、零 Fail 应为 `1498-1-0`：

```text
Score = floor((1498 + 1/2) / 1499 * 1,000,000)
      = 999666
```

对话写的是 `1497-1-0`，三项只合计 `1498`，比当前谱面物量少 1。若把 `N` 当作 `1498`，也会得到 `999666`。因此这个样本的分数支持“一 Tune 扣半个音符分”，但判定数量本身少写了一个 Harmony，或使用了物量为 1498 的旧谱面数据。

### 2.3 SolarOrbit：1912-100-7

```text
N = 1912 + 100 + 7 = 2019

      = floor(1962 / 2019 * 1,000,000)
      = 971768
```

与给出的 `971768` 完全一致。

这张谱面每个 Tune 相对 Harmony 约扣：

```text
500,000 / 2019 = 247.647...
```

每个 Fail 相对 Harmony 约扣：

```text
1,000,000 / 2019 = 495.295...
```

### 2.4 Nyarlathotep's Dreamland：2261-20-5

```text
N = 2261 + 20 + 5 = 2286
Score = floor((2261 + 20/2) / 2286 * 1,000,000)
      = floor(2271 / 2286 * 1,000,000)
      = 993438
```

与给出的 `993438` 完全一致。

## 3. 分数、EX 准度与 Rating 准度不是同一个量

Portal 同时返回以下字段：

```text
exScore     = 2H + T
maxExScore  = 2N
exScoreRate = exScore / maxExScore * 100
```

新版游戏分数与 `exScoreRate` 的关系为：

```text
Score = floor(exScoreRate * 10,000)
```

例如 `exScoreRate = 98.9247...%` 时，分数就是 `989247`。

但是 Portal 的 `ratingPercent` 不是简单的 `exScoreRate`，也不是旧公式的判定率。完整换算链是：

```text
H/T/F
  -> x = (2H + T) / (2N)
  -> Score = floor(1,000,000x)
  -> SingleRating = B(C)x + Q(x)
  -> ratingPercent = SingleRating / M(C) * 100
```

因为 `ratingPercent` 最后还除以谱面满 Rating `M(C)`，所以同样的分数准度在不同定数谱面上可以得到不同的 `ratingPercent`。例如同为精确 `x = 0.98`：

| 定数 C | B(C) | M(C) | Single Rating | ratingPercent |
| ---: | ---: | ---: | ---: | ---: |
| 5.0 | 5.00 | 6.50 | 6.2700 | 96.46% |
| 16.0 | 16.50 | 18.00 | 17.5400 | 97.44% |
| 16.5 | 17.25 | 18.75 | 18.2750 | 97.46% |

因此写离线计算器时，不能直接把 `Score / 10,000` 当成 `ratingPercent`。只有 `H/T/F/N` 可用时应直接计算精确 `x`；只有整数分数时可用 `x ~= Score / 1,000,000`，但会丢失总分向下取整前不足 `0.000001` 的准度。

### 3.1 只知道整数分数、总物量和定数时的精确逆推

若已知新版整数分数 `S` 和总物量 `N`，虽然不知道 `H/T/F`，仍可利用 `EX = 2H + T` 必为整数这一条件还原精确准度。由：

```text
S = floor(1,000,000 * EX / (2N))
```

得到：

```text
2NS / 1,000,000 <= EX < 2N(S + 1) / 1,000,000
```

Lanota 的实际谱面均远小于 500,000 物量，因此这个区间宽度 `2N / 1,000,000` 小于 `1`，最多只能容纳一个整数。对有效的新版分数：

```text
EX = ceil(2NS / 1,000,000)
x = EX / (2N)
```

计算后应再次验证：

```text
floor(1,000,000 * EX / (2N)) == S
```

若验证失败，说明分数、总物量或版本至少有一项不匹配。得到 `x` 后，再依次计算 `B(C)`、`M(C)`、`Q(x)`、Single Rating 和 `ratingPercent`，不需要知道 Tune 与 Fail 的具体数量。

还能还原总失分单位：

```text
T + 2F = 2N - EX
```

但仅凭分数无法把它唯一拆成 `T` 和 `F`；这不影响新版 Rating，因为两者只通过 `T + 2F` 生效。

以 `Immaculate` 的 `S = 934838`、`N = 2701`、`C = 16.5` 为例：

```text
2N = 5402

EX 下界 = 5402 * 934838 / 1,000,000
          = 5049.994876

EX 上界 = 5402 * 934839 / 1,000,000
          = 5050.000278

唯一整数 EX = 5050
x = 5050 / 5402
  = 0.934838948537...

总失分单位 = 5402 - 5050 = 352
所以只知道 T + 2F = 352
```

随后代入 `C = 16.5` 的 Rating 公式：

```text
B(C) = 17.25
M(C) = 18.75
Q(x) = 7x - 5.4

RawSingleRating = 17.25x + Q(x)
                = 17.269844502036...
SingleRating = 17.26（向下截断）

ratingPercent = 17.269844502036... / 18.75 * 100
              = 92.105837344193...%
显示为 92.10%（向下截断）
```

## 4. 非满分 Rating 公式的推导与验证

### 4.1 同分控分实验：Tune 与 Fail 只通过分数生效

在 `Igallta` Whisper 上进行控制变量实验：

| H-T-F | N | 精确 x | 分数 | ratingPercent | Single Rating |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 480-20-0 | 500 | 98.00% | 980000 | 96.46% | 6.27 |
| 485-10-5 | 500 | 98.00% | 980000 | 96.46% | 6.27 |
| 490-0-10 | 500 | 98.00% | 980000 | 96.46% | 6.27 |

三次游玩的 Tune/Fail 组成不同，但 `T + 2F` 都等于 `20`，因此 `x` 和分数相同；Portal 的 `ratingPercent` 与 Single Rating 也完全相同。这排除了 Tune、Fail 分别进入 Rating 公式的假设，也确认新版 Rating 不含连击项。对 Rating 而言，一个 Fail 与两个 Tune 等价。

### 4.2 旧公式不能原样继续使用

旧版常见计算式为：

```text
OldPercent = (H + T/3) / N
OldSingleRating = OldPercent * 旧等级上限
```

旧公式会让同分的三组控分样本得到不同结果，因此可以直接排除。例如三组 `980000` 样本的旧判定率分别是 `97.33%`、`97.67%`、`98.00%`，而新版 Portal 三组均为 `96.46%`。

### 4.3 分段函数的精确验算

`Igallta` 的 `C = 5.0`，所以 `B(C) = 5.0`、`M(C) = 6.5`。以 `480-20-0` 为例：

```text
x = 0.98
Q(x) = 6 * 0.98 - 4.51 = 1.37
SingleRating = 5 * 0.98 + 1.37 = 6.27
ratingPercent = 6.27 / 6.5 * 100
              = 96.461538...%
Portal 截断显示 = 96.46%
```

`497-1-2` 的精确 `x = 0.995`：

```text
Q(x) = 7 * 0.995 - 5.5 = 1.465
SingleRating = 5 * 0.995 + 1.465 = 6.44
ratingPercent = 6.44 / 6.5 * 100
              = 99.076923...%
Portal 截断显示 = 99.07%
```

`Immaculate` Master 的 `C = 16.5`，所以 `B(C) = 17.25`、`M(C) = 18.75`。新版实测 `2447-156-98`：

```text
N = 2701
x = (2 * 2447 + 156) / (2 * 2701)
  = 5050 / 5402
  = 0.9348389485...
Score = 934838
Q(x) = 7x - 5.4 = 1.1438726397...
RawSingleRating = 17.25x + Q(x)
                = 17.2698445020...
SingleRating = max(0, RawSingleRating)
             = 17.2698445020...
Portal 截断显示 = 17.26
ratingPercent = 17.2698445020... / 18.75 * 100
              = 92.1058373441...%
Portal 截断显示 = 92.10%
```

这里不能把页面已经显示的 `17.26` 再除以 `18.75`：

```text
17.26 / 18.75 * 100 = 92.053333...% -> 92.05%
```

它与 Portal 的 `92.10%` 不同，因为 `17.26` 已经丢掉了精确 Single Rating 的小数部分。后台实际处理顺序是：

```text
精确 SingleRating 17.2698445020...
├─ 单独向下截断 -> singleRating 17.26
└─ 先除以满值 18.75 -> 92.1058373441...% -> 单独向下截断 -> ratingPercent 92.10%
```

最后把公式用于当前 Portal 的全部 B30/R15 条目：去除 B30 与 R15 中重复出现的同一游玩记录后，共得到 44 条独立记录。对每条记录都使用精确的 `H/T/F/N` 计算 `x`，结果为：

```text
Single Rating 两位小数命中：44 / 44
ratingPercent 两位小数命中：44 / 44
```

这也解释了为什么把不同谱面的 `ratingPercent` 直接对游戏分数做一条直线拟合只能得到近似值：基础 Rating `B(C)` 和分母 `M(C)` 随谱面定数变化，而 `Q(x)` 本身还有 `95%`、`98%`、`99%` 三个分段点。

## 5. 满 Single Rating 公式的证据

从当前账号的满分成绩与官方定数直接读取到：

| 官方定数 C | 满 Single Rating | 对应公式 |
| ---: | ---: | --- |
| 10.0 | 11.50 | `C + 1.5` |
| 11.0 | 12.50 | `C + 1.5` |
| 12.0 | 13.50 | `C + 1.5` |
| 13.0 | 14.50 | `C + 1.5` |
| 13.5 | 15.00 | `C + 1.5` |
| 14.5 | 16.00 | `C + 1.5` |
| 14.8 | 16.30 | `C + 1.5` |
| 15.0 | 16.50 | 两段交点 |
| 15.3 | 16.95 | `1.5C - 6` |
| 15.5 | 17.25 | `1.5C - 6` |
| 15.8 | 17.70 | `1.5C - 6` |
| 16.0 | 18.00 | `1.5C - 6` |
| 16.5 | 18.75 | `1.5C - 6` |

所以对话中的高难例子：

```text
15.0 -> 16.50
15.3 -> 16.95
15.5 -> 17.25
15.8 -> 17.70
16.0 -> 18.00
16.5 -> 18.75
```

全部严格满足 `1.5C - 6`。

对话所说“1～14 仍是等级 + 0.5”与当前 Portal 满分记录不符。若这里的“等级”指官方定数 `C`，正确值是 `C + 1.5`；例如 `14.8` 满 Rating 为 `16.30`，不可能是 `15.30`。

## 6. B30/R5 的实测验算

本次账号 Portal 返回：

```text
玩家 Rating：17.22
Best 30 calculatedRating：14.81
Recent 15 calculatedRating：2.40
```

用 API 显示到两位小数的单曲 Rating 验算：

```text
B30 的 30 项之和 = 518.39
518.39 / 35 = 14.811142... -> 14.81
```

Recent 15 中最高五项是：

```text
16.97, 16.92, 16.89, 16.84, 16.53
```

所以：

```text
R5 项之和 = 84.15
84.15 / 35 = 2.404285... -> 2.40

总 Rating = (518.39 + 84.15) / 35
            = 17.215428...
            -> 17.22
```

这解释了为什么官网会出现“B30 是 15.05、R5 是 2.x，而两者相加刚好是玩家 Rating”：两个栏目展示的是各自对最终值的贡献。

Portal 当前页面也明确写明：Recent Rating 取最近 15 次游玩中的最高 5 个 Single Rating，再除以 35。

## 8. Portal 数据使用注意

单曲详情接口可能同时出现：

- `score = 1000000`；
- 但 `singleRating`、`ratingRecord.harmony/tune/fail` 仍对应另一场非满分记录。

本次在 `Let's go now` 上就观察到了这种情况。说明 `score` 是最高游戏分，而 `ratingRecord` 是另一套有明细的 Rating 记录，两者不保证来自同一场游玩。反推时必须使用同一个 Rating 条目的 `playedAt` 聚焦记录，不能把单曲最高分和未对齐的判定明细直接拼在一起。

## 9. 低准度分段的补充验证

最初样本的最低准度为 `x = 0.922251...`，只能确认 `90%～95%` 段的 `Q(x) = 7x - 5.4`，不能把这条直线直接外推到零分。随后在 500 物量的 `Igallta` Whisper 得到两条新版即时成绩：

| H-T-F | x | 分数 | Portal Single Rating | Portal ratingPercent |
| ---: | ---: | ---: | ---: | ---: |
| 425-0-75 | 85% | 850000 | 5.09 | 78.46% |
| 230-0-270 | 46% | 460000 | 2.76 | 42.46% |

两条记录都满足最低段：

```text
Q(x) = x
SingleRating = B(C)x + x
             = (B(C) + 1)x
```

对 `Igallta` 的 `B(C) = 5`：

```text
x = 0.85：SingleRating = 6 * 0.85 = 5.10
          ratingPercent = 5.10 / 6.5 * 100 = 78.461538...% -> 78.46%

x = 0.46：SingleRating = 6 * 0.46 = 2.76
          ratingPercent = 2.76 / 6.5 * 100 = 42.461538...% -> 42.46%
```

Portal 在 `850000` 条目中显示 `singleRating = 5.09`，不是数学十进制结果 `5.10`。原因是服务端采用二进制浮点数后直接向下截断：其内部 `5.1 * 100` 实际为 `509.99999999999994`，再执行 `floor` 得到 `509`。这是显示实现的浮点边界现象，不代表公式系数偏离 `6`。

最低段与下一段在 `x = 0.90` 连续：

```text
最低段：Q(0.90) = 0.90
下一段：7 * 0.90 - 5.40 = 0.90
```

因此完整公式共有 `0%`、`90%`、`95%`、`98%`、`99%`、`100%` 六个关键点和五个线性区间；在最低段中 Single Rating 与 `x` 成正比，只有零分 `x = 0` 才得到 `0` Rating。

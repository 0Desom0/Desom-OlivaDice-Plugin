# Lanota 新版计分与 Rating 公式

> 整理日期：2026-08-01
>
> 数据来源：Desom 的 Lanota Portal Best 30、Recent 15、单曲详情与同谱面控分成绩
>
> 验证结果：当前 44 条不重复 B30/R15 记录的 Single Rating 与 ratingPercent 均全部命中

本文按以下顺序组织：

1. 公式速查：拿到分数、总物量、定数后直接计算；
2. 完整例题：用 `Immaculate 934838` 逐步演算；
3. 数据验证：按五个分数区间整理实测证据；
4. 满 Single Rating、B30、R5 与总 Rating；
5. 数据对齐、截断和浮点数注意事项。

## 1. 公式速查

### 1.1 符号

| 符号 | 含义 |
| --- | --- |
| `H` | Harmony 数量 |
| `T` | Tune 数量 |
| `F` | Fail 数量 |
| `N` | 总物量，`N = H + T + F` |
| `S` | 新版整数分数，范围 `0～1000000` |
| `EX` | Rating Score，`EX = 2H + T` |
| `x` | 精确分数准度，范围 `0～1` |
| `C` | 谱面官方定数 |
| `B` | 谱面基础 Rating |
| `M` | 谱面满分 Single Rating |
| `R` | 未截断的精确 Single Rating |
| `P` | 未截断的 ratingPercent，单位为百分比 |

### 1.2 已知分数、总物量、定数时

输入：

```text
S = 新版整数分数
N = 总物量
C = 谱面定数
```

第一步，还原整数 `EX`：

```text
EX = ceil(2NS / 1000000)
```

只使用整数运算时：

```text
EX = (2NS + 999999) // 1000000
```

必须验证输入互相匹配：

```text
floor(1000000 * EX / (2N)) == S
```

若验证失败，说明分数不是新版分数，或总物量、谱面版本至少有一项不正确。

第二步，计算精确准度：

```text
x = EX / (2N)
```

第三步，根据定数计算 `B` 与 `M`：

| 定数范围 | 基础 Rating `B` | 满分 Rating `M` |
| --- | ---: | ---: |
| `C <= 15` | `C` | `C + 1.5` |
| `C > 15` | `1.5C - 7.5` | `1.5C - 6` |

第四步，按 `x` 所在区间计算精确 Single Rating `R`：

| 精确准度 `x` | 整数分数范围 | Single Rating 公式 |
| --- | ---: | --- |
| `0 <= x < 0.90` | `0～899999` | `R = (B + 1)x` |
| `0.90 <= x < 0.95` | `900000～949999` | `R = (B + 7)x - 5.40` |
| `0.95 <= x < 0.98` | `950000～979999` | `R = (B + 4)x - 2.55` |
| `0.98 <= x < 0.99` | `980000～989999` | `R = (B + 6)x - 4.51` |
| `0.99 <= x <= 1` | `990000～1000000` | `R = (B + 7)x - 5.50` |

最终取值：

```text
精确 Single Rating = max(0, R)
P = R / M * 100
```

页面/API 的两位小数显示值：

```text
显示 Single Rating = floor(R * 100) / 100
显示 ratingPercent = floor(P * 100) / 100
```

`R` 和 `P` 必须分别从未截断值计算。不能先把 `R` 截成两位小数，再用显示值反推 `P`。

### 1.3 已知判定明细时

若已知 `H/T/F`，不需要从整数分数逆推：

```text
N = H + T + F
EX = 2H + T
x = EX / (2N)
S = floor(1000000x)
```

等价写法：

```text
x = (H + T/2) / N
```

相对全 Harmony：

```text
1 Tune 扣分 = 500000 / N
1 Fail 扣分 = 1000000 / N
```

因此一个 Fail 严格等价于两个 Tune，新版分数与 Single Rating 都没有连击项。

### 1.4 能从分数恢复什么

由 `S` 和 `N` 恢复 `EX` 后，还能得到：

```text
T + 2F = 2N - EX
```

这个值是总失分单位。仅凭分数不能把它唯一拆成 Tune 和 Fail，但新版 Single Rating 只依赖 `x`，不需要知道具体拆分。

Lanota 实际谱面远小于 500000 物量，`EX` 候选区间的宽度 `2N/1000000` 小于 `1`，所以有效分数最多对应一个整数 `EX`。

### 1.5 五段函数的连续点

把 `R = Bx + Q(x)` 拆开时，分数修正项 `Q(x)` 为：

| `x` 范围 | `Q(x)` |
| --- | --- |
| `0～0.90` | `x` |
| `0.90～0.95` | `7x - 5.40` |
| `0.95～0.98` | `4x - 2.55` |
| `0.98～0.99` | `6x - 4.51` |
| `0.99～1.00` | `7x - 5.50` |

各段在边界连续：

| `x` | `Q(x)` |
| ---: | ---: |
| `0.00` | `0.00` |
| `0.90` | `0.90` |
| `0.95` | `1.25` |
| `0.98` | `1.37` |
| `0.99` | `1.43` |
| `1.00` | `1.50` |

因为最低段 `R = (B + 1)x` 且所有谱面的 `B + 1 > 0`，所以精确 Single Rating 只有在 `x = 0` 时才等于 `0`。极小的正数仍可能因两位小数截断而显示为 `0.00`。

### 1.6 ratingPercent 不等于分数准度

`ratingPercent` 是当前 Single Rating 相对谱面满值 `M` 的比率：

```text
P = R / M * 100
```

同样的 `x` 在不同定数上可以得到不同的 `P`。以 `x = 0.98` 为例：

| `C` | `B` | `M` | 精确 `R` | 显示 `P` |
| ---: | ---: | ---: | ---: | ---: |
| `5.0` | `5.00` | `6.50` | `6.2700` | `96.46%` |
| `16.0` | `16.50` | `18.00` | `17.5400` | `97.44%` |
| `16.5` | `17.25` | `18.75` | `18.2750` | `97.46%` |

## 2. 完整例题：Immaculate 934838

### 2.1 已知数据

| 项目 | 数值 |
| --- | ---: |
| 整数分数 `S` | `934838` |
| 总物量 `N` | `2701` |
| 谱面定数 `C` | `16.5` |
| API Single Rating | `17.26` |
| API ratingPercent | `92.10%` |

本例只使用 `S/N/C` 计算，暂不使用 API 中的 `H/T/F`。

### 2.2 恢复 EX 与精确准度

```text
2N = 5402

EX 下界 = 5402 * 934838 / 1000000
          = 5049.994876

EX 上界 = 5402 * 934839 / 1000000
          = 5050.000278

唯一整数 EX = 5050
x = 5050 / 5402
  = 0.934838948537...
```

验证原分数：

```text
floor(1000000 * 5050 / 5402)
= floor(934838.948537...)
= 934838
```

还能恢复总失分单位：

```text
T + 2F = 5402 - 5050 = 352
```

API 实际判定为 `2447-156-98`，确有 `156 + 2 * 98 = 352`。

### 2.3 计算 Single Rating

`C = 16.5 > 15`：

```text
B = 1.5 * 16.5 - 7.5 = 17.25
M = 1.5 * 16.5 - 6 = 18.75
```

`x = 0.934838...` 落在 `0.90～0.95`：

```text
R = (B + 7)x - 5.40
  = 24.25 * 5050 / 5402 - 5.40
  = 17.269844502036...
```

向下截断到两位小数：

```text
显示 Single Rating = 17.26
```

### 2.4 计算 ratingPercent

必须使用未截断的 `R`：

```text
P = 17.269844502036... / 18.75 * 100
  = 92.105837344193...%

显示 ratingPercent = 92.10%
```

不能使用已经显示的 `17.26` 反推：

```text
17.26 / 18.75 * 100
= 92.053333...%
-> 92.05%
```

两个 API 字段的正确生成顺序是：

```text
精确 R = 17.269844502036...
├─ 独立截断 -> Single Rating 17.26
└─ 先除以 M -> 92.105837344193...% -> 独立截断 -> 92.10%
```

## 4. 满 Single Rating

### 4.1 满值公式

满分时 `x = 1`，所以：

```text
M(C) = B(C) + 1.5
```

即：

```text
当 C <= 15：M(C) = C + 1.5
当 C > 15： M(C) = 1.5C - 6
```

两段在 `C = 15` 时都等于 `16.50`，连续衔接。

### 4.2 定数与满值对照

| `C` | 满 Single Rating `M` | 公式 |
| ---: | ---: | --- |
| `10.0` | `11.50` | `C + 1.5` |
| `11.0` | `12.50` | `C + 1.5` |
| `12.0` | `13.50` | `C + 1.5` |
| `13.0` | `14.50` | `C + 1.5` |
| `13.5` | `15.00` | `C + 1.5` |
| `14.5` | `16.00` | `C + 1.5` |
| `14.8` | `16.30` | `C + 1.5` |
| `15.0` | `16.50` | 两段交点 |
| `15.3` | `16.95` | `1.5C - 6` |
| `15.5` | `17.25` | `1.5C - 6` |
| `15.8` | `17.70` | `1.5C - 6` |
| `16.0` | `18.00` | `1.5C - 6` |
| `16.5` | `18.75` | `1.5C - 6` |

因此低定数不是“定数 + 0.5”，而是 `C + 1.5`；例如 `C = 14.8` 的满值是 `16.30`。

## 5. B30、R5 与总 Rating

### 5.1 聚合公式

```text
B30乐曲 = Best 30 的 30 个 Single Rating 之和 / 35
R5贡献 = 最近 15 次游玩中最高 5 个 Single Rating 之和 / 35
总Rating = (B30单曲和 + R5单曲和) / 35
```

Recent 栏目包含最近 15 次游玩，但只有其中最高 5 次参与 R5。同一谱面可以在 R5 中重复出现。

### 5.2 当前 Portal 快照

| 项目 | API 显示值 |
| --- | ---: |
| 玩家 Rating | `17.22` |
| B30 乐曲 | `14.82` |
| R5 贡献 | `2.39` |

B30 的 30 个 API 显示 Single Rating 之和：

```text
518.90 / 35 = 14.825714... -> API 14.82
```

当前 Recent 15 中最高五项：

| 排名 | 曲目 | Single Rating |

## 6. 数据与显示注意事项

### 6.1 必须对齐同一次游玩

单曲详情可能同时出现：

- `score` 是该谱面的历史最高游戏分；
- `singleRating` 和 `ratingRecord` 来自另一场有判定明细的游玩。

反推时必须使用同一个 Rating 条目的 `playedAt` 对齐数据，不能把最高分和另一场 `H/T/F` 拼在一起。本次在 `Let's go now` 上观察到过这种错位。

只知道别人的 `S/N/C` 时不受这个问题影响：直接按第 1.2 节从分数和物量恢复 `EX` 即可，但前提是分数来自新版无连击计分，并且物量属于同一谱面版本。

### 6.2 两位小数是向下截断

Portal 的 Single Rating 与 ratingPercent 从各自未截断结果独立向下截断，不是普通四舍五入。

`Igallta 850000` 是一个二进制浮点边界案例：

```text
C = 5，B = 5，x = 0.85
数学结果 R = (B + 1)x = 6 * 0.85 = 5.10
```

服务端使用二进制浮点数时：

```text
5.1 * 100 = 509.99999999999994
floor(...) = 509
API Single Rating = 5.09
```

但 ratingPercent 使用未截断的 `R`：

```text
5.10 / 6.5 * 100
= 78.461538...%
-> API 78.46%
```

若需要逐位复现 Portal，必须考虑这种 IEEE 754 浮点数加 `floor` 的边界行为。

### 6.3 零 Rating 与显示 0.00

精确 Single Rating 只有零分时为 `0`：

```text
x = 0 -> R = 0
x > 0 -> R > 0
```

但非常小的正数可能在截断后显示成 `0.00`。因此“页面显示 0.00”不一定代表内部精确 Rating 等于零。
